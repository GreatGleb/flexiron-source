# Длинная ночь: 12+ часов

Замеры сняты по ночи `night-2026-09-24-2225` (она же — последняя на 2026-09-26).
Числа устаревают молча: пересчитывай по `supervisor.json` и `СВОДКА.md` свежего прогона,
а не по этому файлу.

## Что известно из последнего прогона — и это меняет настройки

| что | замер |
|---|---|
| длительность | 22:25 → 10:38 = **12 ч 13 мин** |
| порций | 20 |
| остановка | **«порции кончились»**, а не часы и не токены |
| токенов (супервизор) | **25 483 903** |
| расход | **2.1 млн/час** |
| порция | **~37 минут** |
| принято / забраковано | 33 / 32 |

Два вывода, без которых длинная ночь оборвётся сама:

1. **Дефолт `FLEXIRON_TOKENS=26000000` почти связал прошлый прогон** — израсходовано 25.48 млн
   из 26. Ночь на 13 часов при 2.1 млн/час просит ~27 млн, то есть с дефолтом она встанет на
   токенах около двенадцатого часа. Потолок поднимать обязательно.
2. **Останавливали порции, а не время.** `FLEXIRON_MAX_BATCHES` по умолчанию 8; прошлый раз
   стояло 20, и их хватило ровно на 12 часов. Чтобы связывающим ограничением были ЧАСЫ (так
   понятнее и предсказуемее), порций надо заведомо больше, чем ночь успеет.

## Настройки на 13 часов

```bash
FLEXIRON_HOURS=13 \
FLEXIRON_TOKENS=60000000 \
FLEXIRON_MAX_BATCHES=30 \
FLEXIRON_IDLE_LIMIT=5 \
roo_code/workflows/night-run.sh
```

| переменная | значение | почему именно оно |
|---|---|---|
| `FLEXIRON_HOURS` | 13 | «12 с лишним», как прошлый раз, но теперь связывает время |
| `FLEXIRON_TOKENS` | 60 млн | заведомо НЕ связывает: 13 ч × 2.1 млн = ~27 млн. Решение владельца 2026-09-24: до 4 утра потолка нет, после — 30 млн; супервизор такого правила не знает, его бюджет один и кумулятивный, поэтому ставится не связывающее число |
| `FLEXIRON_MAX_BATCHES` | 30 | при ~37 мин на порцию 13 часов это ~21 порция; тридцать оставляют запас, и ночь кончится по часам |
| `FLEXIRON_IDLE_LIMIT` | 5 | см. ниже — это единственная настройка, где есть выбор |
| `FLEXIRON_PARALLEL` | 4 (дефолт) | проверено прошлым прогоном, не трогать без причины |
| `FLEXIRON_BATCH` | 5 (дефолт) | то же |
| `FLEXIRON_FINISH` | 120 (дефолт) | срок `FLEXIRON_HOURS` — последний момент, когда задача НАЧИНАЕТСЯ; начатым дают столько минут сверх срока на доделку. Автору отведено до 90 минут, плюс проверки и приёмка. Ночь поэтому может кончиться позже срока — на время последней задачи. `0` — прежний обрыв на сроке вместе с прогоном |

### Про `IDLE_LIMIT` выбор действительно есть

Это «сколько порций подряд без ПРИНЯТЫХ задач заканчивают ночь»; `0` — не заканчивать вовсе.

- **3 (дефолт)** бережёт токены, когда работа кончилась, но обрывает ночь на неудачной полосе.
  При прошлом соотношении 33/32 полоса из трёх пустых порций вполне вероятна;
- **0** гарантирует, что ночь доживёт до часов, и рискует сжечь несколько часов впустую, если
  работа действительно кончилась;
- **5** — середина: полосу из трёх-четырёх переживёт, бесконечно молотить пустоту не станет.

Рекомендация — 5. Это компромисс, а не замер: полос длиной пять подряд у нас ещё не было, и
проверить это можно только следующим прогоном.

## Чем занять 13 часов

Источник работы — планы, оператор режет порции сам. Но перед этой ночью он обязан прочитать
[`незакрытое-после-ночи-2026-09-24.md`](незакрытое-после-ночи-2026-09-24.md), иначе потратит
порции впустую:

- **двадцать из тридцати двух** забракованных задач **уже сделаны руками** коммитами
  `recover(...)` (§2 того файла; таблица сведена по заголовкам коммитов и помечена как гипотеза
  — проверять грепом, а не названием);
- **двенадцать** браков были не работой, а сломанной общей базой — причина устранена (БАГ-05,
  клон базы на задачу), повториться по ней они не могут (§1);
- настоящий остаток — примерно двенадцать имён (§3);
- задача с `mocks/*` или `domain/*` в `outputs` обязана нести `npm run test:audit` отдельной
  строкой в `checks`: `npm run verify` аудит-набор не гоняет, и это уже стоило красного CI (§6).

## Что проверить ДО запуска

1. **Дерево чистое.** `night-run.sh` отказывается работать в занятом дереве (код 3). Незапушенные
   коммиты запуску не мешают — мешают несохранённые правки;
2. **ничего не запущено** — ни `vite`, ни `playwright`: ночь гоняет проверки и подерётся за порт;
3. **файл маршрутизации существует** — `~/.config/flexiron/night-routing.json`, иначе код 2;
4. **база 5433 поднята** (`flexiron_pg_verify`): схемные задачи без неё бракуются;
5. если автором ставится Zoo Code / DeepSeek — **VS Code открыт на этом репозитории и Zoo Code
   запущен**: его исполнитель работает в папке, на которой открыт редактор, и сокет
   `/tmp/zoo-code.sock` должен отвечать.

## Маршрутизация: кто пишет, кто принимает

Живой файл — `~/.config/flexiron/night-routing.json` (вне репозитория). Сейчас в нём
Sonnet пишет, Opus принимает. Образец связки с DeepSeek лежит в репозитории:
[`headless-routing.json`](../../workflows/headless-routing.json) — `work` на `zoo` через сокет,
`review` на Sonnet.

| связка | замер цены за задачу | чем известна |
|---|---|---|
| Sonnet → Opus | $3.11 | прошла целиком 2026-09-23 и всю ночь 2026-09-24 |
| DeepSeek → Sonnet | **$1.77** | прошла 2026-09-23; автор дешевле в девять раз ($0.09), платит приёмка |

**Приёмку дешевле автора делать нельзя** и не надо: `load_routing` роняет прогон, если обе роли
отданы одному бэкенду с теми же параметрами — приёмка не делается тем, кто писал.

**Риск DeepSeek, названный прямо.** Автор может вернуть прозу вместо JSON. Раньше это валило
ВЕСЬ прогон (ночь 2026-09-23-2241 кончилась так в 01:51 из 05:40). **Сейчас — нет:** в ночь
2026-09-24 такой ответ получила задача `notifications-client-refusals-and-polling`, и прогон
продолжился до двадцатой порции. То есть ветка отказа изолирована, и для длинной ночи это
решающее улучшение. Проверять на своём прогоне всё равно стоит: если ночь оборвётся в первые
часы — смотреть `supervisor.json`, поле `stopped`.

Второй риск, дороже первого: **критерий, сформулированный как машинная проверка, будет
удовлетворён буквально.** DeepSeek однажды «починил» битую ссылку, перенумеровав её на строку,
где нужный токен есть, — но на другом элементе, и предложение стало утверждать обратное правде.
Резолвер позеленел, приёмка пропустила. Критерии писать про утверждение («документ говорит
правду»), а не про признак («резолвер зелёный»).

## После ночи

- ветка `auto/night-<дата>`; скрипт **не возвращается** на `main` и ничего не пушит;
- сводка при любом исходе: `~/.local/share/flexiron/night-<дата>/СВОДКА.md`, пересобрать —
  `night-report.py --out <каталог>`;
- читать сводку не по числу «принято», а по разбору: прошлый раз «забраковано 32» означало
  двенадцать задач инфраструктуры и двадцать уже сделанных.
