# Сквозные правила: сводка для доменов

Шесть тем: правило, что делает домен, гейт. Подробности — в плане по ссылке; свой файл прогнать
`contractRefs.spec.ts`, битых 0.

## 1. [Права (§6)](сквозное-rights-план.md)

Правило. Домен не заводит своего механизма прав; вопрос один — есть ли у пользователя действие
`A` на элементе `E`; действий четыре: `read`, `edit`, `create`, `delete`. Отказ — 403 `FORBIDDEN`,
своих кодов нет; величина без права вырезается, а не помечается.

Домен. `## Права домена` + три таблицы: элементы `домен.идентификатор` (≥1 `entity` на сущность) ·
эндпоинт → элемент и действие, ровно раз каждый · дефолт по семи строчным ролям. Действие —
умолчание по методу (`GET` read, `POST` create, `PATCH`/`PUT` edit, `DELETE` delete), отступ только
по П15 с причиной в 4-м столбце; права нет → `—` + `не требуется` + причина из трёх: `публичный`,
`служебный`, `собственные данные`. Ещё Д5–Д10: вырезаемое с арифметическим замыканием либо
«вырезать нечего», `owner` на журнал, готовность прав, роут → элемент.

Гейт: `rights-contract-conformance.spec.ts` в `npm run test:unit`.

## 2. [Мультиарендность (§4)](сквозное-tenancy-план.md)

Правило. Арендатор — только из токена; каждая функция с `select`/`update`/`delete` по тенантской
таблице принимает `tenant_id` и сужает им запрос: писатель — в своём `where`, сшитый ответ — в
каждом источнике; уникальность — парой с арендатором. Исключение одно: запрос, узнающий арендатора.

Домен. Таблицы домена; по каждой функции — сужает ли; несужённая → `TENANTLESS` с причиной либо
дефект (баг-файл + `KNOWN_GAPS`); роут и `schemas.py` `tenant_id` не принимают;
`UniqueConstraint`/`unique=True` — с `tenant_id` (модель и миграция вместе); сервис не шлёт
`tenantId`/`X-Tenant`; категория А/Б/В у всех таблиц, включая будущие (по умолчанию А).

Гейт: `cd backend && python3 -m unittest discover -s tests -t .`; `tenant-not-sent.spec.ts`.

## 3. [Аудит-лог (§9)](сквозное-audit-log-план.md)

Правило. Хранилище одно — `audit_entries` (своей таблицы и формы записи домен не заводит), ключ
UUIDv7, срока хранения нет. Пишет домен, владеющий видом сущности из замкнутого перечня: каждая
меняющая состояние операция оставляет след — запись на каждое изменённое свойство. Не пишутся
чтение, сущность вне перечня и событие без всех пяти полей строки (сущность, свойство, было, стало,
автор) — оно в серверный ярус.

Домен. Мутирующие операции — счётом по моку, с их свойствами; `sensitive` всегда, значением или
`null`; запись удаляет `owner` путём своей сущности, чужая или неизвестная →
`AUDIT_ENTRY_NOT_FOUND`; удаление сущности чистит записи кодом; домен без вида пишет это строкой.

Гейт: `mocks/audit-writers.spec.ts` и `mocks/audit-shape.spec.ts`.

## 4. [Уведомления (§10)](сквозное-notifications-план.md)

Правило. Типов пятнадцать, коды в плане, шестнадцатого домен не заводит. Эмиттер зовётся в условии
перехода, а не из чтения; повтор отличает база уникальным `eventKey`; кому доставлено — право, что
видно — подписка (сайт работает и назад, почта только вперёд); флаг тревоги несут ровно три кода.

Домен. Раздел `## События домена (§10)`: код · переход ссылкой `файл:строка` · условие ·
дискриминатор · флаг тревоги; без событий — дословно `Событий домена нет.` Ещё: `entityType`, роут,
шаблон на три языка. Нельзя: отбирать тревоги, заводить чистку, писать мимо эмиттера.

Гейт: `notification-events-conformance.spec.ts` и `mocks/notification-triggers.spec.ts`.

## 5. [Идемпотентность (§11)](сквозное-idempotency-план.md)

Правило. Необратима операция, двигающая склад или деньги, шлющая наружу неотзываемое или
создающая запись, которую интерфейс не даёт удалить; сомнение — в пользу «необратима». Ей нужен
`Idempotency-Key` (UUID v4 на жест, 24 часа): без него `VALIDATION_ERROR` 422, повтор → сохранённый
ответ дословно, повтор до завершения первого → `CONFLICT` 409. Save одной транзакцией — только
`orders` и `warehouse`; версия записи — только `orders`, у прочих last-write-wins.

Домен. Каждый `### POST /api/...` — одна строка: «обязателен» с ценой повтора и ссылкой либо «не
требуется — операция обратима (чем)»; по дословной строке на файл про атомарность Save и версию;
расхождение — в баг-файл, не в контракт.

Гейт: Г1–Г5: `POST` помечен раз, строки Save и версии по одной.

## 6. [Кастомные поля (§8)](сквозное-custom-fields-план.md)

Правило. `config` и `categories` не сливаются, третьего перечня типов поля нет; сервер читает из
значения только `fieldId` и `value`, валидирует по определению (четыре кода `FIELD_VALUE_*`, 422).
Значение переживает определение: снятое поле и значения не удаляются, по снятому не отдаются и не
принимаются, возврат отдаёт те же. Снятие, скрывающее значение, требует права (владелец, админ;
иначе 403 без проверки кода) и кода подтверждения заголовком `X-Confirmation-Code`:
`FIELD_REMOVAL_CONFIRM_REQUIRED` 409, `FIELD_REMOVAL_CONFIRM_INVALID` 422.

Домен. Дословно `Кастомных полей у домена нет.` либо `Кастомные поля: да.` + ссылка. Блоки:
Б — `config`/`categories`, В — `products`, Г — `warehouse` (нет значения = «неизвестно»),
Д — `settings`/`auth`/`uploads`/`audit-feed`, А — прочие 13.

Гейт: `custom-fields-conformance.spec.ts`.
