## 2. Главное ограничение — запросы в день, а не деньги

Без покупки кредитов: 50 запросов в день — **одна-две задачи**. Ночи так не набрать.

С покупкой от $10 (разово, «за всё время»): 1000 запросов в день ≈ **30 задач в сутки** при
~33 запросах на задачу — больше, чем успевает ночь с одним автором (2.7 задачи/ч на Zoo 26-го).
Лимит 20 в минуту на одного автора не связывает: 33 запроса за 20–40 минут — 1–2 в минуту.

Отсюда же следствие: **брак стоит квоты.** Задача, забракованная приёмкой, съела свои ~33
запросов. Очередь под слабую модель важнее, чем раньше (§5).

## 3. Решения владельца (до начала работ)

1. **Купить $10 кредитов OpenRouter или нет.** Без них переход бессмыслен (§2). Кредиты не
   сгорают на бесплатных моделях и потом годятся для платных.
2. **Приватность.** Бесплатные эндпоинты OpenRouter, как правило, требуют разрешить провайдерам
   использовать запросы (настройки приватности аккаунта). Автор получает код заказчика целиком.
   Допустимо ли это по договору — решает владелец, не прогон.
3. **Модель по умолчанию** — после пробы §4.2, из 2–3 кандидатов. Без предпочтения владельца
   выбирается та, что прошла пробу с наименьшим числом запросов.

## 4. Этапы

**Связь проверена 2026-09-29:** сокет поднят (ярлык `~/.local/share/applications/code.desktop` ставит
`ROO_CODE_IPC_SOCKET_PATH` при запуске из меню), профиль `default` → OpenRouter, модель `openrouter/free`;
проба на чтение через `zoo-ipc-client.mjs` — `done`, верный JSON, 2 запроса, $0.

### 4.1 Подготовка среды — без правок кода (~20 мин, руками владельца)

1. Ключ OpenRouter — в профиль Zoo Code через интерфейс расширения (он ляжет в секреты VS Code,
   не в репозиторий). Профиль назвать `openrouter-free`, модель — первый кандидат.
2. Обновить список моделей в профиле (кэш от 3 июля) и записать, какие `:free` живы сегодня.
3. VS Code, открытый **на `~/PycharmProjects/flexiron-source`**, перезапустить с
   `ROO_CODE_IPC_SOCKET_PATH=/tmp/zoo-code.sock code ~/PycharmProjects/flexiron-source`.
   Проверка: `ls -la /tmp/zoo-code.sock` — сокет есть.
4. Файл `~/.config/flexiron/night-routing-zoo-openrouter.json` (вне репозитория): `work` —
   `zoo`, сокет, `timeout_seconds: 5400`, `configuration` с именем профиля; `review` — `claude`,
   `claude-opus-5`, как у aider. Точные ключи `configuration` (имя профиля, `apiProvider`,
   `openRouterModelId`) **снять с `dist` расширения**, а не угадывать — правило 3 ROO.md.
   Ключ API в этот файл не кладётся.

### 4.2 Проба одной задачей (~1 ч, расход ~50–150 запросов)

Цель — замер, а не работа. Взять уже решённую задачу с известной приёмкой (например,
`expect-budget-tohaveurl-clients-layout` из ночи 26-го: 44 вызова у DeepSeek), прогнать её
клиентом с `--result` на копии checkout для каждого кандидата. Записать:

- сколько запросов (по `api_req_started` в `tasks/<id>/ui_messages.json` Zoo — клиент их не
  сохраняет);
- вернул ли JSON через `attempt_completion` или прозу;
- был ли 429 и что сделал Zoo: автоповтор или `api_req_failed` с ожиданием;
- время и прошла бы приёмка.

**Стоп-условие:** если ни один кандидат не довёл задачу до приёмки — переход не делается, а
владельцу приносится замер. Если 429 кончается `api_req_failed` и ожиданием — сначала §4.3 п.2.

Журнал пробы — `roo_code/roo-context/verify-runs/zoo-openrouter-probe-2026-09-<дд>.md`.

### 4.3 Правки обвязки (ветка `fix/zoo-openrouter`, каждая с тестом в `test_headless_backends.py` / `test_night_run.py`)

По важности:

1. ✅ **Запрет параллели для Zoo** (сделано 2026-09-29, `load_routing(..., parallel)`, признак `follows_root` у бэкенда) — без этого первая же ночь с дефолтным `--parallel 4` отдаст
   Zoo основной checkout, пока ядро ждёт правок в `wt-*`. `load_routing` или `preflight`
   отвергает `zoo` в роли `work` при `parallel > 1` с понятной причиной. Тест: маршрутизация с
   `zoo` + `parallel=2` → `ValueError`; с `parallel=1` — проходит.
2. **Отказ провайдера у Zoo** — клиент собирает тексты ошибок (`api_req_failed`, реплики
   `error`) в поле отчёта, бэкенд прогоняет их через `provider_refusal`. В `PROVIDER_REFUSALS`
   добавить дневную квоту бесплатных моделей OpenRouter — **точный текст ошибки взять из пробы
   §4.2**, не из памяти. Минутный 429 сюда не входит: он лечится повтором. Итог — ночь
   останавливается с `PROVIDER_REFUSAL_PREFIX`, и сторож её не поднимает ([night-watchdog.py:61](../../workflows/night-watchdog.py#L61)).
3. **Ответ на `api_req_failed`** — только если проба показала, что 429 останавливает задачу.
   Клиент отвечает «повторить» после паузы, не больше N раз; команду ответа через IPC снять с
   `dist`. Иначе задача висит до таймаута 5400 с и съедает ночь.
4. **Признак жизни для сторожа** — клиент дописывает событие в свой лог в каталоге прогона по
   мере работы (а не только в конце), чтобы 45 минут тишины значили зависание, а не долгую
   задачу. Проверить замером на пробе: самый длинный промежуток без событий Zoo.
5. **Счёт запросов в сводке** — `night-report.py` показывает деньги DeepSeek; для Zoo нужны
   запросы к модели за ночь и на задачу, иначе к утру не видно, сколько квоты осталось.

Приёмка ветки — цикл [verify.md](../../skills/verify.md) (Б-линзы для питона обвязки) и
отдельный агент-скептик; мерж `--no-ff`, без пуша.

Оператор ([operator-prompt.md](../../workflows/operator-prompt.md)) о типе автора не знает.
На первые ночи — задачи механические, с машинным критерием и малыми outputs. Кандидаты уже есть:
недоделки ночи `2026-09-28-2152` (`short-refs-warehouse`,
`short-refs-auth-categories-bcc`, две забракованные) — перепись ссылок, ровно такая работа.
Широкие правки кода и бэкенд-слайсы — только после ночи, где приёмка приняла ≥ 60 %.

Правка промпта оператора — отдельным пунктом, если первая ночь покажет брак на крупных задачах;
заранее её не делать (замер до постройки).

### 4.5 Первая ночь

```bash

FLEXIRON_PARALLEL=1 FLEXIRON_PEAK=ignore FLEXIRON_HOURS=7 \
```

Условия: дерево чистое, VS Code с сокетом открыт на checkout и **владелец в нём не работает**
(Zoo правит файлы в том же окне). Запускает владелец:
классификатор авто-режима запуск ночи отклоняет.

Утром — `night-report.py`: принято/забраковано, запросы на задачу, причина остановки. Решение
о продолжении — по доле принятых и числу запросов на принятую задачу.

## 6. Риски

- **Качество бесплатных моделей неизвестно.** Страховка — приёмка Opus, но она стоит лимита
  Claude на каждую задачу, в том числе забракованную (замер 2026-09-23: приёмка втрое
  дороже автора). При браке > 50 % лимит Claude уходит на отбраковку.
- **Бесплатные модели пропадают и перегружаются** — список `:free` меняется, провайдеры отдают
  429 чаще платных. Держать в маршрутизации запасную модель и менять её правкой файла.
- **Модель вернёт прозу вместо JSON** — ядро это уже держит: брак одной задачи, а не ночи
  (`f09020b`, `712f473`).
- **Сброс дневного лимита OpenRouter** — время сброса не замерено. Если он приходится на
  середину ночи, п.2 из §4.3 остановит ночь до сброса; продолжение после сброса — вручную или
  отдельной правкой сторожа, не сейчас.
- **Недельный лимит Claude** — приёмка и оператор тратят его как раньше; потолок ночи его и
  считает.
