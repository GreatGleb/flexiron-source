## 3. SEO на github.io

**Сделано 2026-11-21**, шаг 6 — 2026-11-22. Журнал —
`roo_code/roo-context/verify-runs/landing.md`, раздел «Этап 2, пункт 3».

Ограничение честно: чужой домен второго уровня и вложенный путь продвигаются хуже своего домена;
сделать можно всё, кроме этого.

**Решение владельца 2026-11-21:** одна сборка в корне `/Flexiron-Enterprise/`. Лендинг — `/lt/`, `/en/`, `/ru/`,
программа — `/admin/…` рядом; старые ссылки `/demo/…` переадресуются на новое место. Переход лендинг → демо
остаётся внутри одного приложения, механизм языка (`useLandingAppLang`) не меняется.

Публикуется не отсюда: сборка копируется в репозиторий `GreatGleb/Flexiron-Enterprise` (локально
`../Flexiron-Enterprise`, Pages из корня). Замер 2026-11-21: там `404.html`, `.nojekyll`, `README.md`, `demo/`;
корень отвечает 404, `greatgleb.github.io/robots.txt` — 404 (корневого сайта нет, robots.txt не на что положить).

Шаги:

1. **Адреса.** `base` сборки `/Flexiron-Enterprise/`, папка сборки `../site`. Роутер: `/demo/:путь` → `/:путь`.
   `public/404.html` — новая база. Инлайновый скрипт `index.html`, восстанавливая путь после 404, убирает
   заранее отрисованную разметку лендинга — иначе на `/admin/…` мелькнёт лендинг до запуска приложения.
2. **Голова страницы** по языку: `canonical`, `hreflang` (lt, en, `x-default` → lt; русского нет), `robots noindex`
   на `/ru`, Open Graph и Twitter (заголовок, описание, адрес, картинка, `og:locale`), JSON-LD
   (`SoftwareApplication` + `Organization`). Адрес сайта — `VITE_SITE_URL`, по умолчанию
   `https://greatgleb.github.io/Flexiron-Enterprise`. Уход с лендинга снимает эти теги.
3. **Картинки превью** для соцсетей — `public/og/{lt,en,ru}.jpg` 1200×630 (первый экран), снимаются тем же
   скриптом, что скриншоты.
4. **Заранее отрисованный HTML** — `scripts/prerender-landing.mjs` после `vite build`: открывает собранный сайт,
   сохраняет готовую разметку `/lt/`, `/en/`, `/ru/` и корня (корень = литовская страница с `canonical` на `/lt/`),
   снимает классы появления (иначе без JS текст невидим), пишет `sitemap.xml` (lt и en с `hreflang`). Сам себя
   проверяет: h1 своего языка, `canonical`, `noindex` у ru, нет `reveal-pending` — не сошлось, сборка падает.
   Команда — `npm run build:site`. GitHub отдаёт эти страницы с кодом 200, а не через 404-переадресацию.
5. **Скорость:** скриншот первого экрана — `fetchpriority="high"`, остальные — `loading="lazy"`.
6. **Search Console:** свойство по префиксу URL `https://greatgleb.github.io/Flexiron-Enterprise/`,
   аккаунт `flexiron.erp@gmail.com`. Подтверждается **HTML-файлом** `public/google2553ae2d9808c47d.html` —
   удалять нельзя, Google перепроверяет его регулярно. `public/googleec9ee7e6eaa8cd90.html` — первое
   подтверждение, ошибочно с другого аккаунта владельца; убрать, когда владелец решит. `sitemap.xml` отправлен (2026-11-22).
   Мета-тег через `VITE_GSC_VERIFICATION` остаётся запасным способом и сейчас не задан.
7. **Публикация:** `scripts/publish-pages.sh` — сборка, копирование `site/` в `../Flexiron-Enterprise/` с
   сохранением `.git`, `README.md`, `.nojekyll`; старая папка `demo/` уходит (её ссылки ловит роутер).
   Push — владелец.
8. **Тесты:** e2e головы страницы на трёх языках и её очистки после ухода; самопроверка пререндера.

## 4. Языки: литовский основным, английский переключателем, русский по адресу

**Решения владельца 2026-11-21** (заменяют прежнюю «секретную ссылку»; язык взят раньше SEO):

| Вопрос | Решение |
|---|---|
| Адреса | у каждого языка свой: `/lt`, `/en`, `/ru`; корень `/` ведёт на `/lt` |
| Переключатель | в шапке, только LT / EN; русского в нём нет — `/ru` знает только тот, кому дали ссылку |
| Скриншоты | на каждый язык свои — пересняты с демо тем же сценарием, что для презентации |
| Перевод | LT и EN переводит агент, публикуется без вычитки носителем |
| Язык программы | по версии лендинга, с которой в неё ушли — даже поверх прежнего выбора |
| Русский в программе | скрыт для всех, кто пришёл не с `/ru`: нет кнопки RU, нет русского запасным переводом, нет упоминаний на LT/EN лендинге — в Литве русский многими воспринимается болезненно |

Как устроено:

- Тексты — `src/content/landing.{lt,en,ru}.ts`, одна форма `LandingContent`; страница берёт набор по
  `route.meta.landingLang`. Компоненты не импортируют язык напрямую — спрашивают текущий набор.
- Картинки — `src/assets/images/landing/{lt,en,ru}/`, у всех трёх одни имена и размеры.
- `<html lang>` и заголовок/описание страницы — по языку; Turnstile берёт язык из `<html lang>`.
- Уход с лендинга в программу (демо, «Войти», подвал) — на языке этой версии, **поверх** выбора, сделанного
  раньше в программе (решение владельца 2026-11-21: «с ру — админка на русском, с литовской — на литовском»).
  Один общий охранник роутера (`useLandingAppLang`), язык — из маршрута, с которого ушли: `/lt` и `/en` —
  одна страница, `onBeforeRouteLeave` остался бы привязан к первому языку.
- `/ru` закрывается от индексации (`noindex`) в пункте SEO.
- Русский скрыт (`src/i18n/ruVisibility.ts`, флаг `flexiron_ru` в браузере): виден только пришедшим с `/ru`
  и тем, у кого язык уже сохранён как `ru`. Уход с `/lt` или `/en` флаг снимает. Без флага — нет RU в трёх
  переключателях (`useVisibleLocales`), `tf()` не берёт русский запасным, на LT/EN лендинге «два языка: литовский
  и английский». Русские строки в демо-данных (314 шт., `src/mocks/`, `services/mocks/`) переведены на английский —
  это заодно правило «русского в моках нет».
- Сторож — `tests/e2e/ru-hidden.spec.ts`: все публичные и админские страницы на lt и en без кириллицы (текст,
  поля, подписи) и без кнопки RU. Не видит окна, вкладки и выпадающие списки — только первый экран.
- Подпись переключателя для экранного диктора (источник для `landing.ru.ts`): «Язык».
- Сверки: русский — с презентацией и этим планом (как было); литовский и английский — той же формы, что
  русский (ключи, длины списков, имена картинок), без кириллицы.
