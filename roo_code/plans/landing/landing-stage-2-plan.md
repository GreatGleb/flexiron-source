## 1. Заявки: Turnstile + Telegram + таблица

**Сделано 2026-11-21.** Скрипт развёрнут под `flexiron.erp@gmail.com` (таблица «Flexiron — заявки с сайта»),
адрес — в `frontend_vue/.env`. Живая заявка с localhost дошла в Telegram и в лист `Leads`.
Журнал проверок — `roo_code/roo-context/verify-runs/landing.md`, раздел «Этап 2, пункт 1».

Всё в одном `doPost` из [`apps-script/landing-leads/Code.gs`](../../../apps-script/landing-leads/Code.gs):

1. Фронт: виджет Turnstile в форме, токен уходит в теле запроса вместе с полями.
   Без токена кнопка не отправляет. Ловушка `website` остаётся вторым рубежом.
2. Скрипт: проверка токена `POST https://challenges.cloudflare.com/turnstile/v0/siteverify`
   (`UrlFetchApp`, секрет — в Script Properties). Не прошла → ответ ошибкой, строки нет.
3. Прошла → строка в лист `Leads` (как сейчас) → `sendMessage` Bot API в чат владельца.
   Сбой Telegram не теряет заявку: строка уже записана, ошибка отправки — в отдельный столбец.
4. Секреты (`TURNSTILE_SECRET`, `TG_BOT_TOKEN`, `TG_CHAT_ID`) — только в Script Properties.
   Во фронте — лишь публичный site key Turnstile (`VITE_TURNSTILE_SITE_KEY`).

Тексты формы (источник для `landing.ru.ts`; `landing.ru.spec.ts` сверяет их с этим файлом):

- заявка верна, проверка ещё не пройдена — «Подтвердите, что вы не робот, — заявка уйдёт сразу после проверки»;
- скрипт капчи не загрузился — «Проверка от ботов не загрузилась. Обновите страницу или напишите нам напрямую:»,
  ниже контакты.

Скрипт виджета грузится при первом касании формы, а не со страницей: меньше чужого кода для тех,
кто заявку не оставляет, и e2e без формы в сеть не ходят.

**От владельца:** бот у @BotFather (токен); написать боту одно сообщение — по нему берётся
`chat_id`; аккаунт Cloudflare и виджет Turnstile на домены `greatgleb.github.io` и `localhost`
(site key + secret).

Ограничение честно: чужой домен второго уровня и вложенный путь продвигаются хуже своего домена;
сделать можно всё, кроме этого.

- Заранее отрисованный HTML лендинга при сборке (сейчас текст появляется только после JS).
  Без новых зависимостей — проверить, хватит ли своего скрипта на уже стоящем Playwright.
- `title`, `description`, Open Graph и картинка для превью, `canonical`, `lang="lt"`.
- Разметка schema.org (`SoftwareApplication` / `Organization`).
- `sitemap.xml`; `robots.txt` действует только в корне хоста (`greatgleb.github.io/robots.txt`,
  репозиторий `greatgleb.github.io`) — выяснить, есть ли он.
- Search Console: свойство по префиксу URL, подтверждение мета-тегом.
- Скорость: картинки в webp/avif, размеры заданы, LCP первого экрана.
- **Решено 2026-11-21:** лендинг переезжает из `/Flexiron-Enterprise/demo/` в корень
  `/Flexiron-Enterprise/`, приложение демо остаётся глубже. Как разнести сборку — в детальном плане.
  Публикуется не отсюда: сборка этого репозитория копируется в отдельный репозиторий
  `GreatGleb/Flexiron-Enterprise` (локально `../Flexiron-Enterprise`, Pages из корня; порядок — README.md

  Корневой `404.html` сейчас уводит любой неизвестный путь на базу демо — проверить, что лендинг он не задевает.
  `greatgleb.github.io/robots.txt` — 404 (корневого сайта нет): ограничений нет, sitemap — через Search Console.

## 4. Языки: литовский основным, английский переключателем, русский по адресу

**Решения владельца 2026-11-21** (заменяют прежнюю «секретную ссылку»; язык взят раньше SEO):

| Вопрос | Решение |
|---|---|
| Адреса | у каждого языка свой: `/lt`, `/en`, `/ru`; корень `/` ведёт на `/lt` |
| Переключатель | в шапке, только LT / EN; русского в нём нет — `/ru` знает только тот, кому дали ссылку |
| Скриншоты | на каждый язык свои — пересняты с демо тем же сценарием, что для презентации |
| Перевод | LT и EN переводит агент, публикуется без вычитки носителем |
| Язык программы | по версии лендинга, с которой в неё ушли — даже поверх прежнего выбора |
| Русский в программе | скрыт для всех, кто пришёл не с `/ru`: нет кнопки RU, нет русского запасным переводом, нет упоминаний на LT/EN лендинге — в Литве русский многими воспринимается болезненно |

Как устроено:

- Тексты — `src/content/landing.{lt,en,ru}.ts`, одна форма `LandingContent`; страница берёт набор по
  `route.meta.landingLang`. Компоненты не импортируют язык напрямую — спрашивают текущий набор.
- Картинки — `src/assets/images/landing/{lt,en,ru}/`, у всех трёх одни имена и размеры.
- `<html lang>` и заголовок/описание страницы — по языку; Turnstile берёт язык из `<html lang>`.
- Уход с лендинга в программу (демо, «Войти», подвал) — на языке этой версии, **поверх** выбора, сделанного
  раньше в программе (решение владельца 2026-11-21: «с ру — админка на русском, с литовской — на литовском»).
  Один общий охранник роутера (`useLandingAppLang`), язык — из маршрута, с которого ушли: `/lt` и `/en` —
  одна страница, `onBeforeRouteLeave` остался бы привязан к первому языку.
- `/ru` закрывается от индексации (`noindex`) в пункте SEO.
- Русский скрыт (`src/i18n/ruVisibility.ts`, флаг `flexiron_ru` в браузере): виден только пришедшим с `/ru`
  и тем, у кого язык уже сохранён как `ru`. Уход с `/lt` или `/en` флаг снимает. Без флага — нет RU в трёх
  переключателях (`useVisibleLocales`), `tf()` не берёт русский запасным, на LT/EN лендинге «два языка: литовский
  и английский». Русские строки в демо-данных (314 шт., `src/mocks/`, `services/mocks/`) переведены на английский —
  это заодно правило «русского в моках нет».
- Сторож — `tests/e2e/ru-hidden.spec.ts`: все публичные и админские страницы на lt и en без кириллицы (текст,
  поля, подписи) и без кнопки RU. Не видит окна, вкладки и выпадающие списки — только первый экран.
- Подпись переключателя для экранного диктора (источник для `landing.ru.ts`): «Язык».
- Сверки: русский — с презентацией и этим планом (как было); литовский и английский — той же формы, что
  русский (ключи, длины списков, имена картинок), без кириллицы.
