### Решения (и почему)
- **Порядок проверок поля:** пусто → `required` (только имя и контакт); длиннее лимита → `tooLong`; контакт
  не телефон и не e-mail → `invalidContact`. Длина считается после `trim()`.
- **Телефон** — план говорит «≥7 цифр». Я добавил: строка состоит только из цифр и `+ - ( ) .`/пробела
  (`PHONE_RE`), иначе «звоните 1234567» прошло бы как телефон. **E-mail** — «`@` и точка в домене»:
  `EMAIL_RE` требует непустые части домена между точками (`a@mail.`, `a@.ru`, `a@mail..ru` — нет). Обе
  формулировки уже́ плана, но в его рамках; если владелец хочет мягче — правка одного выражения в двух местах.
- **Ловушка на сервере не проверяется:** по плану `website` в payload не входит (список полей payload в плане
  без него), поэтому бот отсекается только на клиенте (`isHoneypot` → форма показывает «успех» без отправки — L-06).
- **`rejected` vs `failed`:** HTTP-статус не 2xx, не-JSON, JSON без булева `ok`, сеть, таймаут → `failed`;
  только явное `{ok:false}` → `rejected`. `{"ok":"true"}` — `failed`, а не `sent`.
- **`META_MAX = 500` в Code.gs** — обрезка `page`/`userAgent` только на сервере, чтобы в таблицу не легло что
  угодно длинное. Числа нет в плане; это техническая защита листа, не текст для человека. На клиенте этих
  полей человек не вводит, лимита в `LIMITS` нет.
- **Шапка листа пишется только на пустой лист** (`getLastRow() === 0`). В dicktris шапка «чинится» перезаписью
  строки 1 — здесь это затёрло бы заявку, если владелец сам создал лист и что-то в него положил.
- **Сбой почты не роняет заявку:** письмо уходит после записи и вне замка, ошибка — в `console.error`.
- **Л5 проверяется не только разбором, но и исполнением:** спека грузит Code.gs в `node:vm` с заглушками
  `SpreadsheetApp/LockService/PropertiesService/MailApp/ContentService` и гоняет 17 входов через `doPost` и
  `validateLead` — вердикты обязаны совпасть. Разбор констант ловит смену числа, исполнение — снятую проверку
  при целой константе (инверсия «проверка комментария снята» краснит только исполнение).
- `eslint-disable-next-line sonarjs/code-eval` на одной строке спеки (`runInContext(CODE_GS, …)`): исполняется
  файл из репозитория — ради этого спека и написана. Вызовы `doGet/doPost` берутся свойством контекста, без eval.
- README не повторяет числа лимитов (ссылается на константы Code.gs) — иначе третья копия, которая устареет молча.
