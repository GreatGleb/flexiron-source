# План: продающий лендинг Flexiron (страница `/`)

Маршрут: `/` (имя `landing`). На демо — https://greatgleb.github.io/Flexiron-Enterprise/demo/
Файлы: `frontend_vue/src/views/public/LandingPage.vue` + `frontend_vue/src/components/landing/*`
Очередь для прогона: [`tasks.json`](tasks.json) (формат — как у ночного прогона 3D_website:
`rules` + задачи с `depends / inputs / result / touches / done / checks`).
Скилы: [`create-page.md`](../../skills/create-page.md), [`vue-rules.md`](../../skills/vue-rules.md),
[`verify.md`](../../skills/verify.md) — читаются до кода.

## Цель

Владелец металлобазы, который о Flexiron не слышал ничего, за одну прокрутку понимает:
что это, какие его потери закрывает, что программа уже реально умеет, — и оставляет заявку
на показ. Второе действие — «открыть демо» и потрогать живую программу на демо-данных.

Источник смысла и текстов — презентация от 2026-11-17:
[`presentation/build.js`](presentation/build.js) (тексты 11 слайдов),
[`presentation/Flexiron-презентация.pptx`](presentation/Flexiron-презентация.pptx),
скриншоты — [`presentation/img/`](presentation/img/).
Образец по подаче — лендинг AIQME (https://greatgleb.github.io/3d-fabrication-web/legacy-landing/github-pages/):
крупный hero, полноширинные секции, появление блоков при прокрутке, форма заявки в конце,
контактный баннер. Дизайн-основа — существующий Flexiron (тёмное стекло, Inter, `--primary`).

## Решения владельца (2026-11-20)

| Вопрос | Решение |
|---|---|
| Где живёт | заменяет текущую `LandingPage.vue` (корень SPA = корень демо) |
| Главное действие | заявка на демонстрацию / звонок |
| Куда уходит заявка | Google-таблица через Google Apps Script (как в dicktris: веб-приложение `/exec`, POST `text/plain`) |
| Контакты | заглушки в одном конфиге, владелец заменит |
| Язык | только русский на первом этапе |

## Решения, принятые при написании плана (прогон их не пересматривает)

1. **Тексты лендинга — не в vue-i18n.** `localeParity.spec.ts` требует одинаковый набор ключей
   в ru/en/lt, а переводов пока нет. Тексты живут в типизированном модуле
   `src/content/landing.ru.ts`. Когда появятся переводы — переезд в `src/i18n/public.ts`
   отдельной задачей. Старые ключи `landing.*` в `public.ts` удаляются из всех трёх локалей
   (иначе — мёртвые ключи); `landing.seo.*` тоже переезжают в модуль.
2. **Переключатель языка на лендинге скрыт** (meta маршрута `hideLangSwitcher: true`,
   условие в `App.vue`). `<html lang>` на лендинге — `ru`, при уходе возвращается к локали i18n.
   Проверки переключателя из `tests/e2e/i18n.spec.ts` переносятся с `/` на `/login`.
3. **Демо открывается по-русски.** Кнопка «Открыть демо» перед переходом ставит
   `flexiron_lang = 'ru'`, если пользователь язык ещё не выбирал (ключа нет в localStorage).
   Выбор, сделанный человеком, не перетирается.
4. **Адрес Apps Script — `VITE_LANDING_LEADS_URL`.** Пусто → форма не отправляет, а показывает
   блок «Напишите нам напрямую» с контактами из конфига. Это законное состояние, а не ошибка.
   Для e2e `playwright.config.ts` даёт первому webServer `VITE_LANDING_LEADS_URL=https://leads.invalid/exec`,
   тесты перехватывают его `page.route` (запрос настоящий `fetch`, мок-слой его не касается).
5. **Скрипт Apps Script лежит в репозитории** — `apps-script/landing-leads/Code.gs` + README с
   развёртыванием (по образцу `~/PycharmProjects/dicktris/apps-script/`). Развёртывание
   и вставку URL делает владелец — у прогона нет доступа к его Google.
6. **Правда, а не украшения.** Никаких выдуманных клиентов, отзывов, логотипов, цифр «экономии»,
   «сотен компаний». Только то, что есть в презентации и в коде. Блок «Уже в системе / В разработке»
   переносится честно, как на слайде 11. Скриншоты подписаны: «из работающей программы на
   демонстрационных данных».
7. **Без новых зависимостей.** Анимации — IntersectionObserver + CSS/WAAPI, без GSAP и т.п.
8. **Скриншоты — из презентации**, копируются в `src/assets/images/landing/` как есть (jpg,
   100–300 КБ). У каждого `<img>` — `width`/`height`, `alt` по-русски, ниже первого экрана — `loading="lazy"`.

## Форма заявки

Поля: **Имя*** (≤100), **Компания** (≤150), **Телефон или e-mail*** (≤150; телефон —
≥7 цифр, или e-mail с `@` и точкой в домене), **Комментарий** (≤1000, плейсхолдер
«Сколько у вас складов, сколько менеджеров, что сейчас ведёте в Excel»), скрытое поле-ловушка
`website` (заполнено → тихо «успех» без отправки). Кнопка «Отправить заявку».
Под кнопкой: «Нажимая кнопку, вы соглашаетесь на обработку контактных данных для связи по заявке».

Состояния (`data-state` на форме): `idle` → `sending` (кнопка заблокирована) → `success`
(«Спасибо! Свяжемся в течение рабочего дня» вместо формы) | `error` («Не удалось отправить.
Напишите нам напрямую:» + контакты, введённое не теряется) | `disabled` (URL пуст — блок
контактов вместо кнопки отправки). Ошибки валидации — у поля, по `blur` и на submit,
фокус на первое неверное поле.

Отправка: `fetch(URL, { method: 'POST', headers: { 'Content-Type': 'text/plain' },
body: JSON.stringify(payload), redirect: 'follow', signal: AbortSignal.timeout(15000) })`.
`text/plain` — чтобы не было CORS-preflight (Apps Script его не обслуживает). Ответ `{ ok: true }`
или `{ ok: false, error }`. Payload: `{ name, company, contact, message, page: location.href,
userAgent }`, строки обрезаны `trim()`, пустые → `''`.

Apps Script (`Code.gs`): лист `Leads` создаётся сам, шапка `Дата | Имя | Компания | Контакт |
Комментарий | Страница | Браузер`. Серверная валидация повторяет клиентскую (те же лимиты),
`LockService`, каждая строка с ведущим апострофом (формула не исполнится), `doGet` → `{ ok: true }`
для проверки развёртывания. Уведомление на почту — `MailApp.sendEmail` на адрес из
`PropertiesService` (`NOTIFY_EMAIL`), если задан.

Правило валидации живёт в одном месте — `src/domain/landingLead.ts`; `Code.gs` — вторая
среда исполнения, поэтому лимиты в нём продублированы с комментарием-ссылкой, и юнит-тест
сверяет числа в `Code.gs` с константами домена разбором файла (Л5).

## Дизайн

- Фон — существующие `.bg-image`/`.bg-overlay` из `App.vue` (не трогать). Секции — полупрозрачные
  полосы и стеклянные карточки (`--glass-light`, `--glass-border`, `backdrop-filter`).
- Токены страницы — на `.page-landing` в `src/styles/public/landing.css`:
  `--landing-accent: #f2994a` (оранжевый из презентации — резка/обрезок, «В разработке»),
  `--landing-ok: #27ae60` («Уже в системе»), `--landing-radius: 16px`, `--landing-radius-sm: 10px`,
  `--landing-shadow: 0 24px 60px rgba(0,0,0,.35)`, `--landing-max: 1200px`, `--landing-gutter: clamp(16px, 4vw, 40px)`.
  Синий — только `var(--primary)`/`var(--primary-dark)` из `erp-base.css`, свой синий не заводить.
- Типографика: Inter (уже глобально). H1 `clamp(2.25rem, 5vw, 4rem)`/1.05/800; H2 `clamp(1.75rem, 3.2vw, 2.75rem)`/1.15/700;
  надзаголовки 0.8rem uppercase `letter-spacing: .12em` цвет акцента; текст 1.0625rem/1.6 `var(--text-dim)`.
- Скриншоты — в рамке «окно программы»: стекло, радиус, тень, тонкая полоса с тремя точками
  сверху. Клик по скриншоту не нужен.
- Кнопки лендинга — свои классы `.landing-btn`, `.landing-btn--primary`, `.landing-btn--ghost`
  в `landing.css` (`_buttons.css` на публичных страницах не загружен — питфолл #63).
  Основа — градиент `.cta-button` из `public.css`.
- Все классы страницы с префиксом `landing-` и под `.page-landing` (питфолл #73).
- Брейкпоинты: 1200, 992, 768, 600, 375. На ≤992 фичи в одну колонку (скриншот под текстом),
  шаги контура — 3×2, на ≤600 — столбиком со стрелками вниз; на ≤768 — меню-кнопка в шапке.
  Горизонтальной прокрутки нет ни на одной ширине 320–1440.

## Движение

Параметры появления (образец AIQME V2, `3D_website/legacy-landing/design-previews/animation-v2/README.md`):
`opacity 0→1`, подъём `64px→0`, `1.8s`, `cubic-bezier(.4,0,.2,1)`, задержки соседей `0/160/320 мс`,
запуск при входе в верхние 78 % окна, один раз. Заголовки секций, карточки, шаги контура, скриншоты.
Hero — то же при загрузке, без ожидания прокрутки.

- Композабл `src/composables/useReveal.ts` (IntersectionObserver, `rootMargin: '0px 0px -22% 0px'`),
  директива или ref-функция — на усмотрение задачи, но ОДИН механизм на странице.
- Элементы, уже видимые при загрузке, не скрываются (без мигания): класс `.reveal-pending`
  ставится только элементам ниже окна.
- `prefers-reduced-motion: reduce` → всё видно сразу, без анимации.
- Липкая шапка — фон через класс по скроллу (`scrollY > 8`), слушатель `passive`, снимается в `onUnmounted`.

## Чего НЕ делаем

Видео-фон, 3D, параллакс, калькулятор, тарифы и цены, отзывы, логотипы клиентов, чат-виджет,
аналитика/счётчики, cookie-баннер, EN/LT версии, публикация в Flexiron-Enterprise (делает владелец).

## Порядок работ

Очередь задач — [`tasks.json`](tasks.json): L-01 … L-09. Зависимости там. Кратко:
L-01 тексты/конфиг/картинки → L-02 домен заявки + сервис + Apps Script → L-03 каркас страницы,
маршрут, шапка/подвал, язык → L-04 hero/боли/контур → L-05 фичи/настройка → L-06 демо/дорожная
карта/форма → L-07 движение → L-08 адаптив и доступность → L-09 e2e, сборка демо, финальный свип.

Отображение на фазы `create-page.md`: фазы 1–4 (типы, моки, контракт, композаблы) у лендинга
сводятся к L-01/L-02 — собственных эндпоинтов нет, раздел в `roo-context/api/` не пишется
(внешний Apps Script — не наш API; его контракт — раздел «Форма заявки» выше и `Code.gs`).
Фаза 5 (i18n) — решение 1. Фазы 6–7 — L-03…L-06. Фаза 8 — L-03 (маршрут уже есть; флага нет:
лендинг публичен и не зависит от бэкенда; `ScreensPage` и сайдбар не меняются). Фаза 9 — L-09.
Фаза 10 — L-09 (спека) + точечные спеки в L-02/L-06/L-07.

## Публикация (после прогона, руками владельца)

1. Развернуть `apps-script/landing-leads/Code.gs` по README, вписать URL в
   `frontend_vue/.env` → `VITE_LANDING_LEADS_URL=…`.
2. Заменить заглушки контактов в `src/config/landing.ts`.
3. `cd frontend_vue && npm run build` → по `README.md` корня (rsync `demo/` в `../Flexiron-Enterprise/demo/`), push.
