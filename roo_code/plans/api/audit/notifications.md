## Обязанности сервера

Заполняется как НАБЛЮДЕНИЕ: что знает мок, что знает бэкенд, где во фронте стоит константа
на месте серверного значения. Ответ «нигде» — это не решение, а строка в
`00-решения-владельца.md` с указанием домена.

- Значения по умолчанию и их владелец: ни одного значения домена не принадлежит настройкам арендатора — все стоят константами во фронте. Начальное состояние фильтров `{ type: 'all', isRead: null, search: '', sortBy: 'createdAt', sortDir: 'desc' }` (`src/composables/useNotifications.ts:12-18`) и те же дефолты **вторым экземпляром** в моке (`mocks/index.ts:366-370`). Размер страницы `25` — `usePagination(25)` (`useNotifications.ts:19`) и дефолт мока (`mocks/index.ts:374`); перечень размеров `10/25/50/100` — `PAGE_SIZE_OPTIONS` константой в компоненте (`src/views/admin/notifications/NotificationsPage.vue:74-79`), справочника под него нет ни в настройках, ни на схеме. Интервал опроса `30_000` — дважды в одном файле (`useNotifications.ts:95` дефолтом параметра, `:112` литералом). Дебаунс поиска `300` мс (`NotificationsPage.vue:70`). Размер выдачи дропдауна `5` — `items.value.slice(0, 5)` (`src/components/admin/NotificationDropdown.vue:23`). Иконка типа — `NOTIFICATION_TYPE_ICONS`, константа в типах (`src/types/notifications.ts:35-44`), а не поле записи. ## Правила домена, которых нет в контракте

1. **Форма записи во фронте и схема таблицы расходятся по трём полям.** Фронт: `title`/`message` — `TranslatedString` `{ru,en,lt}` (`src/types/notifications.ts:18-19`), `entityRouteName: string` обязателен (`:22`), `id: string` вида `notif-001`/`notif-ev-001` (`mocks/notifications.ts:21`, `:518`). Схема: `title_translations`/`message_translations` — `JSONB` без ключей (`backend/app/modules/notifications/shared/models.py:29-30`), `entity_route_name` отсутствует вовсе (`:31-32` — только `entity_type: String(50)` и `entity_id: String(100)`), `id` — `UUID` из `UUIDMixin` (`:11`, миграция `:26`). 2. **Уведомление адресное — у него есть владелец-пользователь, и мок этого не знает.** `user_id` объявлен `nullable=False` с индексом (`models.py:22-27`), то есть запись обязана кому-то принадлежать, а лента мока — один общий массив на всех (`mocks/notifications.ts:353`). Все три вопроса «чью ленту читаем», «чей счётчик», «чьё уведомление отмечаем» на фронте не заданы ни разу.
3. **Записи рождаются событиями чужих доменов, а не эндпоинтом уведомлений.** `POST` в домене нет; семь эмиттеров вызываются из `orders`, `warehouse`, `bcc`, `finance` (`mocks/orders.ts:1837,3929,4001`, `mocks/warehouse.ts:789,1710`, `mocks/bcc.ts:368`, `mocks/finance.ts:70,486`). 4. **Событие — это переход, а не момент.** Правило сформулировано в коде дословно (`mocks/notifications.ts:470-473`) и реализовано у каждого вызывающего условием (`orders.ts:1837`, `orders.ts:3929`, `finance.ts:486`, `warehouse.ts:1707-1709`), а не внутри домена уведомлений. 18. **Ошибка чтения ленты доходит до человека как текст исключения, а ошибка счётчика — не доходит никак.** `error.value = (e as Error).message` (`src/composables/useNotifications.ts:37`) и печать этого текста (`src/views/admin/notifications/NotificationsPage.vue:168`); против `catch {}` у счётчика (`useNotifications.ts:46-48`) и у обеих мутаций (`:59-61`, `:69-71`).
