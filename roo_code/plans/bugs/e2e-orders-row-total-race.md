# Дефект: `orders.spec.ts:98` читает сумму из неотфильтрованной строки

**Статус:** ✅ починен 2026-08-18
**Файл:** `frontend_vue/tests/e2e/admin/orders/orders.spec.ts:98`
**Тип:** недетерминизм теста (не дефект приложения)

## Как проявился

Полный прогон 2026-08-18 — 980/982. Падение:

```
Expected: "99897.60"   ← cardGross, карточка ORD-005
Received: "5930.69"    ← listTotal, строка списка
```

Тот же код проходил в трёх полных прогонах ранее в тот же день (961/961, 971/971,
971/971), поэтому «лежавший дефект» отпадает: менялась не программа.

## Что оказалось

Тест ищет заказ, берёт `[data-test="orders-row"]` **первой** и читает сумму. Фильтр
применяется запросом, и до ответа на экране стоит прежняя, неотфильтрованная
таблица. Замеряно:

| | номер | сумма |
|---|---|---|
| первая строка без фильтра | ORD-2026-100 | 5930.69 € |
| первая строка после применения фильтра | ORD-2026-005 | 99897.60 € |
| карточка `/admin/orders/ORD-005` | ORD-2026-005 | 99897.60 € |

То есть `5930.69` — сумма **другого заказа**, ORD-2026-100. Список и карточка ни в
чём не расходились: тест сравнил карточку ORD-005 со строкой ORD-100.

Проверялись версии по порядку:

1. **гонка — подтвердилась.** Ожидание отфильтрованной строки (`toContainText`
   с номером заказа до чтения суммы) даёт 6/6 при `--workers=3 --repeat-each=6`;
2. **дата (`demoClock` через полночь) — проверять не потребовалось:** механизм
   доказан прямо, а не выведен из совпадения по времени. Смена суток объясняет
   лишь то, почему гонка стала проявляться — порядок и суммы заказов сдвинулись,
   и первая строка без фильтра перестала случайно совпадать с ожидаемой;
3. **настоящее расхождение списка и карточки — отпало** (см. таблицу выше).

## Починка

В тест добавлено утверждение номера заказа в строке **до** чтения суммы. Это не
«ожидание ради ожидания»: строка обязана принадлежать искомому заказу, иначе
сравнение сумм не значит ничего.

## Урок

Тот же промах в этой сессии дважды: страница логов читала таблицу до того, как
приходил отфильтрованный ответ. Признак один — **тест ждёт появления элемента, а
не появления нужных данных**. Ждать нужно данные: номер, тип, ключ строки.
