# Ночной пилот через Codex

Подготовлен 2026-09-17. Исполнитель — [codex-night.py](codex-night.py), очередь —
[codex-night-queue.json](codex-night-queue.json). **Живой прогон ещё не запускался.**
Этот пилот готовит три доменных плана; реализация приложения начнётся отдельной
очередью с auth С0 после приёмки его уточнённого плана.

## Что будет происходить без участия владельца

1. Проверка чистого checkout на ветке `auto/*`, наличия источников и CLI.
2. Исходный `npm run verify`. Красный результат останавливает запуск задач.
3. Для каждой задачи: отдельная сессия исполнителя → отдельная сессия проверяющего
   без права записи → `npm run verify` → локальный коммит контроллером.
4. Отчёт с выполненными задачами, коммитами, текущей задачей и причиной остановки.

Порядок пилота: актуализировать auth → устранить замечания к uploads → написать
недостающий backend-план sales-crm. Источники включают заполненный опросник и
П1–П129. Общая очередь находится [здесь](../plans/general/очередь-работ.md).

При первой ошибке, блокировке проверки или нехватке времени пилот останавливается.
Файлы сохраняются в отдельном checkout: они не удаляются и не прячутся в stash.
Нет автоматического слияния, отправки в remote или развёртывания. Это более узкий
режим, чем общая [политика](../plans/general/autonomous-run-policy-plan.md): один
исполнитель за раз, первая ошибка останавливает весь пилот, финального merge нет.
Успешный пилот не означает разрешение на непроверенную реализацию всех доменов.

## Перед первым запуском

Нужны работающий Codex CLI с авторизацией, Git с `user.name`/`user.email`, Node/npm
и установленные зависимости `frontend_vue`. CLI найден в расширении VS Code;
путь можно узнать через `command -v codex`. Если в обычном терминале команда
недоступна, передать её полный путь через `--codex`.

Рабочие изменения от 17 сентября, включая **заполненный опросник**, ещё не были
закоммичены при подготовке пилота. Перед созданием checkout их нужно сохранить
в проверенный локальный baseline-коммит. Checkout от старого HEAD потеряет новые
решения. Не выполнять `git add -A` вслепую при наличии правок из других сессий.
Основной рабочий каталог не использовать для ночи.

После сохранения baseline создать отдельный checkout:

```bash
git worktree add -b auto/codex-pilot ../flexiron-night HEAD
npm --prefix ../flexiron-night/frontend_vue ci
python3 roo_code/workflows/codex-night.py --workspace ../flexiron-night
```

Последняя команда — только preflight, **модель не вызывается**. Установка зависимостей
требует доступа к реестру пакетов; preflight не заменяет исходный `npm run verify`.
Авторизацию и реальный запуск CLI ещё требуется проверить коротким живым пилотом.

## Запуск

Число задач и время задаются явно. Пример для **одной задачи и максимум 60 минут**:

```bash
python3 roo_code/workflows/codex-night.py \
  --workspace ../flexiron-night \
  --run-dir ../flexiron-night-results/pilot-001 \
  --run --minutes 60 --max-tasks 1
```

Это пример параметров, а не согласованный бюджет. Используется модель из текущей
конфигурации Codex; скрипт её не меняет. Ограничение времени включает проверки и обе
сессии, при истечении останавливается группа процессов. Жёсткого денежного лимита
или ограничения токенов здесь нет; оценки недельной квоты Claude не применяются.

Для работы после закрытия терминала запустить ту же команду в `tmux` или через
диспетчер служб. Скрипт сам не устанавливает расписание и не отключает сон.
При локальном запуске компьютер должен оставаться включённым, не спать и иметь
интернет. Закрытый чат не является запущенным ночным процессом. На отдельном сервере
потребуются checkout, зависимости и собственная авторизация Codex.

## Результаты и продолжение

Каталог результатов уникален для каждого запуска. Повторное использование имени
отклоняется: старые журналы никогда не перезаписываются. Он находится вне checkout.

- `report.md` — краткий итог; `state.json` — состояние и коммиты принятых задач.
- `journal.jsonl` — дописываемая последовательность событий, сбрасывается на диск.
- `queue.json`, `schema.json` — точные входные данные запуска.
- `*-work.json`, `*-review.json` — структурированные ответы двух сессий.
- `*.stdout.log`, `*.stderr.log` — реальный вывод CLI, проверок и Git.
- `*.prompt.txt` — точный текст задания для каждой сессии.

SIGTERM/Ctrl+C сохраняют отчёт об остановке. При аварийном отключении питания или
SIGKILL итог может остаться `running`: проверить живые процессы и checkout перед
продолжением. Блокировка в общей Git-директории не допускает одновременных запусков
этого контроллера, но не блокирует ручное редактирование другими программами.

Автоматического resume и повторных починок в первом пилоте нет. После остановки
проверить сохранённые изменения и причину. Принятые задачи исключить из копии
очереди, передать её через `--queue`, использовать новый каталог результатов.
Зависшие/непринятые изменения сохраняются до разбора; новый запуск требует чистого
checkout. Бюджет не входит в тексты задач и не заставляет пересобирать старые брифы.

Старый [night-queue.js](night-queue.js) остаётся сценарием Claude для прежней очереди.
Его дефекты из [остатка работ](../plans/general/остаток-после-прогонов-2026-09-13.md)
этим пилотом не объявляются исправленными.

Проверка контроллера без модели: `python3 roo_code/workflows/test_codex_night.py`.
Реальные флаги сверены с локальным `codex exec --help`; формат запуска, JSONL и
структурированные ответы описаны в
[официальной документации Codex](https://learn.chatgpt.com/docs/non-interactive-mode).
