# Прогон контракта: домен warehouse

Задача: написать `roo-context/api/warehouse.md` по аудиту `plans/api/audit/warehouse.md`.
Ветка `auto/contract-2026-09-04`, автономный режим. Код не тронут — ни одной строки в
`frontend_vue/src` и `backend/`.

Входные числа аудита: эндпоинтов **37**, источник истины «бэкенд» у **0**, решений владельцу
**9**, находок про код **28**. Все четыре подтверждены машиной (см. К1, К3, К5, К6 ниже).

## Что написано

Файл на 1928 строк: шапка со ссылками на соглашения, каталог кодов домена (22 строки),
**37 разделов эндпоинтов**, «Обязанности сервера» (девять граф), «Правила домена» (19 пунктов),
«Клиент написан, UI нет» (пять строк), «Чего в домене нет» (18 строк) и «Пробелы аудита —
состояние» (33 строки, из них 18 помечены «осталось»).

Формат: у каждого из 37 разделов заголовок ровно `### <МЕТОД> <путь>`, строка `Реализация:` и
строка `Бэкенд: не реализован`. Метка `**Статус:** спроектировано` не стоит нигде и стоять не
должна: код есть у всех 37 путей, отсутствует только серверная половина. Динамический сегмент
не развёрнут: `GET /api/warehouse/export/:tab` — один раздел, пять значений (`stock`, `batches`,
`offcuts`, `movements`, `deficit`) списком внутри.

Общие правила не скопированы: **70 упоминаний** параграфов `00-conventions.md`, и задействованы
все двадцать — §1…§20 (`grep -o '§[0-9]*' … | sort -u | wc -l` → 20) — вместо второго экземпляра
правила. Собственных правил домена — 19, они в аудите и больше нигде.

### К7. Ссылки и следы реализации — ЧИСТО, восемь дефектов найдено и починено

Три уровня, каждый со своей инверсией.

**1. Границы.** Скрипт `refcheck2.mjs` вытаскивает все инлайновые `файл:строка` (включая
шорткаты `:NNN`, наследующие файл **в пределах раздела**, как их читает человек) и резолвит по
файловой системе:

```
ссылок встречено=839  резолвится и в границах=839
```

Ноль нерезолвленных, ноль вне границ файла, ноль неоднозначных путей. Внутристрочное
наследование (как в первой версии скрипта) молча пропускало 92 ссылки таблицы кодов — то есть
именно ту дыру, из-за которой прошлые попытки объявляли «не подтверждено 0». Дыру закрыл, и
таблица кодов теперь якорится полным путём в заголовке колонки.

**2. Токен в диапазоне.** Скрипт собирает из окружающего текста токены кода (обратные кавычки,
идентификаторы, строковые литералы) и требует, чтобы хотя бы один был внутри названного
диапазона: **475 подтверждено автоматически**.

**Инверсия:** сдвиг всех диапазонов ломает подтверждение — с 475 до 146 при `--shift=5`, до 166
при `--shift=-5`, до 108 при `--shift=12`. Проверка, одинаково зелёная на верной и неверной
ссылке, не доказала бы ничего; эта — доказывает.

**3. Явная таблица утверждений** на те ссылки, где рядом стоит не токен, а проза («причина
названа», «вызывающий здесь», «функция объявлена»): **241 утверждение вида
`файл|от|до|ожидаемый токен`**, прогон awk-ом:

```
утверждений: 241  провалов: 0
# инверсия: те же 241 со сдвигом +7 → провалов 210 из 241
```

записаны без обратных кавычек (**строка N**), а верные — с ними: иначе резолвер, прогнанный по
этому журналу, посчитал бы цитату неверной ссылки живой ссылкой и покраснел бы на описании
починки.

1. В `services/mocks/warehouse.ts`: `OFFCUT_PRODUCT_MISMATCH` — строка **1090** вместо `:1089`;

   даёт 1089.

   `frontend_vue/src/services/mocks/index.ts:660` и `:705`

Вывод: проверку гонять по каждому написанному файлу, и перегонять после каждой правки ссылок —
починка ссылки двигает наследование у соседей.

отдельный класс дефекта**, и ловится он только тем, что наследование в проверке устроено так же,
как у читателя (по разделу), а не так, как проще запрограммировать (по строке). Первая версия
скрипта пропускала 92 такие ссылки молча и печатала при этом честный ноль непроверенных.
