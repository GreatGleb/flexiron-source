# Пункт 12 — В Firefox полосы прокрутки не наши

План: [`review-followups.md` §12](../../plans/general/review-followups.md).
Решение владельца: **Chrome не трогаем**, Firefox чинится отдельным блоком за `@supports`.

---

## Проверять этот пункт было НЕЧЕМ

Признак готовности — «в Firefox полоса синяя и тонкая, в боковом меню её нет». Firefox на
стенде **не был установлен вовсе**: в `~/.cache/ms-playwright/` лежал только Chromium.

То есть пункт можно было объявить сделанным по чтению CSS, либо написать проверку, которая
молча ничего не проверяет — ровно то, что `verify.md` запрещает про
`pyright … || echo skipping`. Firefox поставлен разово для стенда; в `playwright.config.ts`
он НЕ добавлен, потому что полный набор в двух движках — это отдельное решение, а не
побочный эффект правки полос прокрутки.

**Версия имеет значение.** `npx playwright install firefox` поставил Firefox под 1.62.1,
который npx подтянул сам, а в проекте стоит 1.59.1 — запуск падал на
`Executable doesn't exist at …/firefox-1511`. Ставить надо локальным бинарником:
`./node_modules/.bin/playwright install firefox`.

## Ловушка, из-за которой замер чуть не оказался пустым

**Headless Firefox принудительно ставит `scrollbar-width: none` ВСЕМУ.** Проверено на
пустой странице, где нашего CSS нет вовсе:

```
headless=true  на пустой странице: {"root":"none","div":"none","rootColor":"auto"}
headless=false на пустой странице: {"root":"auto","div":"auto","rootColor":"auto"}
```

Это артефакт Playwright, а не наш стиль. Мерь я только в headless — вывод «в боковом меню
полосы нет» был бы верен для любого элемента любой страницы, и признак готовности
подтвердился бы сам собой, до всякой правки. Питфолл #68 в чистом виде, только не в тесте,
а в стенде.

**Отсюда правило для этого пункта: все замеры полос — только в headed-режиме.**

## База ДО правки (headed, 1440)

| | Firefox | Chromium |
|---|---|---|
| знает `::-webkit-scrollbar` | **False** | True |
| `:root` scrollbar-width / color | auto / auto | auto / auto |
| `.nav` (боковое меню) | auto / auto | auto / auto |
| `.terms-content` (публичная страница) | auto / auto | auto / auto |

То есть в Firefox оформления полос нет никакого — ни цвета, ни скрытия в меню. Дефект
воспроизведён. И `supports(selector(::-webkit-scrollbar)) === false` подтверждает, что
механизм `@supports not selector(…)` в Firefox сработает, а в Chromium — нет, то есть
решение владельца «Chrome не трогаем» держится построением.

## Мёртвый файл

`src/styles/admin/main.css` — 4690 строк, вторая полная копия правил прокрутки и не только.
Не импортирует **никто**: греп по всему репозиторию даёт только упоминания в планах, причём
три разных плана независимо это уже фиксировали. Удалён; `npx vite build` проходит
(`exit=0`, `✓ built in 8.46s`), то есть файл действительно не участвовал в сборке.

Удаление снимает по одной копии из каждой строки таблицы пункта 13 — поэтому 13 и делается
после 12.

## Правка

`src/styles/scrollbars-firefox.css`, подключается из `src/main.ts` — не из
`admin-core.scss`: тот приходит из `AdminLayout` и до публичных страниц не достаёт, а
прокручиваемая область есть и там (`.terms-content`).

## Третья ошибка плана, найденная замером

План: «`scrollbar-width` и `scrollbar-color` наследуются, поэтому достаточно объявить их
один раз на `:root`». **Наследуется только цвет.**

Замер с объявлением обоих свойств на `:root`:

```
FIREFOX  root   {'w': 'thin', 'c': 'rgba(24,144,255,0.5) rgba(0,0,0,0.2)'}
         nav    {'w': 'none', 'c': 'rgba(24,144,255,0.5) rgba(0,0,0,0.2)'}
         terms  {'w': 'auto', 'c': 'rgba(24,144,255,0.5) rgba(0,0,0,0.2)'}   ← ТОЛСТАЯ
```

`.terms-content` получил цвет и остался с системной толщиной. А webkit-правило
`::-webkit-scrollbar { width: 6px }` — селектор УНИВЕРСАЛЬНЫЙ, красит все полосы. То есть
объявление только на корне давало Firefox не то, что имеет Chrome. Разведено: цвет на
`:root` (наследуется), толщина на `*` (нет).

## Замер после правки (headed, 1440)

| | Firefox | Chromium |
|---|---|---|
| знает `::-webkit-scrollbar` | нет → **заходит** в блок | да → **не заходит** |
| `:root` | `thin` + синий | `auto` / `auto` |
| `.nav` (боковое меню) | **`none`** — полоса спрятана | `auto` / `auto` |
| `.terms-content` (публичная) | `thin` + синий | `auto` / `auto` |

Chrome нетронут, и это держится построением, а не аккуратностью.

## Тест: что он может и чего НЕ может

Набор гоняется в одном движке (`playwright.config.ts`, `projects: [chromium]`). Значит
сам вид полосы в Firefox отсюда не проверить, и делать вид, что проверяем, нельзя —
Firefox проверен вручную, headed, замер выше.

Сторожатся две вещи, которые Chromium проверить МОЖЕТ:

1. **решение владельца «Chrome не трогаем»** — вычисленные свойства остаются `auto`.
   Тест краснеет, если кто-то решит «унифицировать оба движка одним правилом» — то есть
   ровно тот вариант, который владелец отклонил;
2. **что файл подключён.** Стиль, который перестали импортировать, не роняет ни сборку,
   ни typecheck, ни один прочий тест — он молча перестаёт действовать, и в Firefox полосы
   тихо возвращаются к системным.

Инверсия:

| сломано | exit |
|---|---|
| контроль | 0 |
| убран `import` из `main.ts` | 1 |
| `@supports not selector(…)` → `@supports (scrollbar-width: thin)` | 1 — падают ОБА кейса: Chromium заходит в блок |
| убрано `.nav { scrollbar-width: none }` | 1 |

В комментарии теста записано предупреждение про headless Firefox — чтобы тот, кто решит
гонять набор во втором движке, не получил «полоса спрятана» бесплатно.
