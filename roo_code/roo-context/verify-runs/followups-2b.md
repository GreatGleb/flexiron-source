Цель: [`review-followups.md` §2b](../../plans/general/review-followups.md) — ветка

## 1. Воспроизведение

Пункт описывает не дефект поведения, а **дыру в покрытии**: ветка есть, теста на неё нет.
Доказывается тем, что имя ветки не встречается нигде, кроме самого хелпера.

```
$ grep -rn "no-mock-module\|no-hook" frontend_vue/src frontend_vue/tests
frontend_vue/tests/e2e/helpers/ready.ts:42:  | 'no-mock-module'
frontend_vue/tests/e2e/helpers/ready.ts:44:  | 'no-hook'
frontend_vue/tests/e2e/helpers/ready.ts:134:          w.__readyExit = 'no-mock-module'
frontend_vue/tests/e2e/helpers/ready.ts:159:          w.__readyExit = w.__mockMode === true ? 'no-traffic' : 'no-hook'
frontend_vue/tests/e2e/helpers/ready.ts:170:    () => ((window as unknown as { __readyExit?: string }).__readyExit ?? 'no-hook') as never,
```

Ни `ready-exits.spec.ts`, ни любой другой спек её не упоминают. Причина, по которой она
недостижима под обычным прогоном, — в [`src/main.ts`](../../../frontend_vue/src/main.ts):

```ts
if (import.meta.env.VITE_USE_MOCKS !== 'false') {
  window.__mockMode = true
  void import('./services/mocks/index')
}
```

Флаг стоит ВСЕГДА, пока сервер поднят с моками, а весь набор ходит на единственный
`npm run dev` (`playwright.config.ts`, один `webServer`). Значит `no-mock-module` за прогон
не исполнялась ни разу. Воспроизведено — пункт актуален.

Замер, подтверждающий, что режим вообще достижим (ручной прогон, до правок):

```
$ VITE_USE_MOCKS=false npx vite --port 5174 --strictPort
  VITE v6.4.3  ready in 195 ms
$ curl -s http://localhost:5174/src/main.ts | head -1
import.meta.env = {… "VITE_USE_MOCKS": "false"}; …
```

То есть переменная окружения доходит до `import.meta.env` в dev-режиме (Vite подмешивает
`process.env`-переменные с префиксом `VITE_` поверх `.env`, где стоит `true`) — проверено,
а не предположено.

Проба браузером в этом режиме (`/admin/settings/units`, `/api/**` подменён через
`page.route`): `__mockMode`, `__mockPending`, `__mockCalls` — все три `undefined`,
запросов 19, видимых скелетов 0. То есть ветка достижима, и страница дорисовывается.

# Заход 2 (2026-08-27): третье утверждение было флейком — и не тем утверждением

Скептик вернул пункт. Вердикт первого захода («3 passed») был снят на удачном стечении
таймингов: у скептика тот же спек падал воспроизводимо — `1 failed, 2 passed`, третий тест,
«ожидание вернулось через 112 мс при задержке 1500 мс», а под нагрузкой — через 243 мс.
Правки первого захода не откатывались: два первых утверждения скептик проверил инверсией и
признал настоящими. Переделано только третье.

## 1. Воспроизведение

**Механика, по чтению кода.** В `tests/e2e/helpers/ready.ts` ожидание в реальном режиме
не держится ни на чём, если страница ещё не нарисована:

- строка 208 `if (await main.count())` — чанка маршрута нет → ожидание монтирования
  пропускается целиком;
- строка 134, ветка `no-mock-module` — решает первым же опросом;
- строка 221 `expect.poll(… .toBe(0))` — на первом опросе видит НОЛЬ скелетов, потому что
  скелетов ещё не существует.

То есть `waited > STALL` в третьем тесте было утверждением не о коде, а о том, кто выиграет
гонку: первый опрос ожидания или первая отрисовка страницы.

**Прогоном.** Прежняя редакция теста восстановлена во временный спек
(`tests/e2e/zz-repro-old-2b.spec.ts`, удалён сразу после прогона) и прогнана под 24
busy-loop на 8 ядрах, `--repeat-each=5`:

```
$ npx playwright test zz-repro-old-2b --repeat-each=5 --reporter=line
exit=1
  Error: ожидание вернулось через 485 мс при задержке 1500 мс
  1 failed
  4 passed (23.0s)
```

Под той же нагрузкой, тем же прогоном, новая редакция:

```
$ npx playwright test ready-real-api --repeat-each=5 --reporter=line
exit=0
  20 passed (57.2s)
```

Воспроизведено — и починено проверяемо, а не «у меня зелено».

## 2. Что изменено

| Файл | Что |
|---|---|
| `tests/e2e/helpers/realApi.ts` | задержка ответов по часам (`delayMs`) заменена на ВОРОТА: `stubRealApi(page, { held: true })` держит каждый ответ до `release()`. Добавлен `holdAppBoot(page)` — удерживает `/src/main.ts`, то есть приложение не запускается, пока тест не отпустит |
| `tests/e2e/ready-real-api.spec.ts` | третий тест разбит на два, оба без гонки |

Приложение (`src/`) не менялось ни строкой; `helpers/ready.ts` не менялся ни строкой
(`git diff --stat` по нему пуст — инверсии ниже откатывались текстовым замещением).

**Почему ворота, а не задержка.** Задержка отвечает на вопрос «сколько ждать», а тесту нужно
удержать СОСТОЯНИЕ до момента проверки. Пока состояние истекало само, тест успевал измерить
не то. Удержанный ответ не истекает, поэтому «страница ещё грузится» перестаёт быть
мгновением, которое надо застать.

### Два новых утверждения вместо одного флейкового

1. **«пока маркер загрузки на экране, ожидание не возвращается».** Ответы удержаны, поэтому
   `.settings-loading` (тот самый класс из `LOADING_MARKERS`) заведомо СТОИТ к моменту, когда
   ожидание начинается — порядок задан, а не выпал. Дальше `Promise.race` с окном 2000 мс:
   ожидание, которое правда ждёт, не вернётся ни через две секунды, ни через час (ответов
   нет), а сломанное возвращается за десятки миллисекунд (112 мс на свободной машине, 243 мс
   под нагрузкой — цифры скептика). Ложным ни в одну сторону это окно быть не может.
   Затем `release()` — и только теперь ожидание вправе вернуться.
2. **«страница ещё не нарисована — ожидание выходит сразу и на пустой экран».** Точка входа
   удержана, `goto(waitUntil: 'commit')`: документ пришёл, Vue не монтировался. Ожидание
   выходит ветвью `no-mock-module`, `#app` пуст, запросов ноль.

Второе — и есть честный ответ на второе следствие пункта 2b, и он хуже, чем было написано в
первом заходе. Признак «данные пришли» в реальном режиме не держится НИ НА ЧЁМ: счётчика
запросов нет (тест 2), а единственная оставшаяся опора — маркер загрузки, которого на
неотрисованной странице ещё не существует. Формулировка первого захода («оставшееся ожидание
— исчезновение скелетов, и оно настоящее») верна только при условии, которое ничем не
обеспечено: скелет уже на экране. Теперь оба случая записаны раздельно и каждый проверяем.

Тест 2 закрепляет ограничение, а не одобряет его: появится в `ready.ts` настоящий признак
для реального режима (ответы `fetch`) — тест покраснеет и потребует переписать себя. Это
проверено инверсией I3 ниже, то есть канарейка живая.
