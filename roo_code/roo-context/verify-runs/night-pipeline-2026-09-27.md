# Конвейер авторов (П3 плана ускорения) — журнал проверки, 2026-09-27

План: [`night-speedup-plan.md`](../../plans/general/night-speedup-plan.md), пункт П3.
Код: `roo_code/workflows/codex-night.py` — режим `--parallel > 1`.

## Что изменилось

Было: пачка авторов пишет разом, ядро ждёт всех, потом по очереди проверки и приёмка.
Стало: автор закончил — его слот сразу берёт следующую задачу (`disjoint_batch` с уже
занятыми файлами), а задача идёт на проверки и приёмку. Подхват повторяется и перед
приёмкой: автор, дописавший во время проверок соседа, не ждёт её конца.

Инварианты: checkout и Git меняет только главный поток; коммит — по одной задаче;
файлы задач в работе (пишутся, ждут, на приёмке) заняты для записи **и чтения**.
Остановка ядра гасит авторов в потоках (`stop_live`) — раньше ядро ждало их до конца.
Повтор приёмки принимает остановку не на первой оставшейся задаче: порядок принятия —
порядок готовности авторов. Трассировка остановки — `stop-traceback.txt` прогона.

## Итерации

1. Задача на приёмке не считалась «в работе» — `fill()` посреди приёмки взял её второй
   раз (`File exists: alpha-work.stdout.log`). Добавлен список `accepting`.
2. Потолок токенов считался по логу автора, который ещё пишет: пустой лог ронял ночь
   (`JSONDecodeError` в `spent_tokens`). Пишущие авторы в счёт не идут до конца.
3. Инверсии, 13 случаев: 10 красных, 3 слепых — неверный сценарий теста подхвата (слот
   сразу брала следующая задача; нужна четвёртая), непроверенное раннее удаление
   worktree (230 МБ `node_modules` на задачу копились бы до конца прогона), сортировка
   готовых по очереди (ничего не утверждала — удалена). После правки: 2 из 2 красные.
