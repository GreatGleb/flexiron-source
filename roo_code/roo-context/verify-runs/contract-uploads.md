# Прогон контракта: домен uploads

Написан [`roo-context/api/uploads.md`](../api/uploads.md) по аудиту
[`plans/api/audit/uploads.md`](../../plans/api/audit/uploads.md). Код не тронут; находки про код
уже лежали в [`contract-sync-uploads-bugs.md`](../../plans/bugs/contract-sync-uploads-bugs.md)
(БАГ-01…БАГ-13) с прошлой задачи и в этом прогоне не менялись.

Домен из одного эндпоинта, но с реализованным бэкендом, поэтому источником истины взят сервер, а
не мок и не `interface UploadedFile`.

## Машинная приёмка

`cd frontend_vue && npm run verify` — четыре прогона, все `exit=0`
(typecheck · lint · dupes · format:check · test:unit; 38 файлов, 783 теста, 2 skip).

Спека К1 подхватила домен автоматически: `[контракт] сведено доменов: 2 · описано эндпоинтов:
6 из 175 · спроектировано впрок: 0`, и `uploads=1` из строки «не сведено» исчез. До задачи было
`сведено доменов: 1 · описано 5 из 175`, `uploads=1` в непокрытых.

### К3. Коды ошибок — сошлось, каталог взят с бэкенда

Подстроки: попарная проверка трёх литералов python-ом → пустой список пар.

факт («под моками все пути ошибок недостижимы»), а не умолчано.

До человека: `grep -rn "upload-error\|uploadError" src/views src/components --include=*.vue` без

### К4. Формы запроса и ответа — сошлось, сверено со схемами сервера
- конверт: `ApiResponse` — `class ApiResponse(BaseModel)` с `success/data/message/code`,

  найдены в `core/uploads/action.py:143-146` (по 1 каждый);

  `grep -cE "original_name|size|mime|uploaded_at"` по `models.py:22-36` → **4**.

**Инверсия:** те же токены в сдвинутом диапазоне `action.py:130-140` → `0`.

### К5. Источник истины — сошлось
