# Две находки, добытые инверсией, и обе шире пункта

## 1. Мой собственный тест был питфоллом #68

Инверсия «убрать серверную постраничность» СНАЧАЛА НЕ ПОКРАСНЕЛА. Разбор:

```ts
await expect(rows.first()).not.toHaveText(firstOnPageOne)   // ❌ истинно всегда
```

`firstOnPageOne` снят через `innerText()` — с табами и переносами. `toHaveText` нормализует
пробелы. Такие строки не совпадут НИКОГДА, то есть `not.toHaveText` выполнялось при любом
коде. Тест был зелёным и на сломанной пагинации.

Замер под инверсией показал, что данные и правда не меняются:
`perPage=50`, счётчик «1-10 of 100», первая строка до и после клика одна и та же.

Исправлено на сравнение одинаковым способом с обеих сторон:

```ts
await expect.poll(async () => (await rows.first().innerText()).trim()).not.toBe(firstOnPageOne)
```

**Отдельный урок про сам приём инверсии:** первый заход давал ложную зелень ещё и потому,
что прогон запускался сразу после записи файла — dev-сервер отдавал старый модуль. Между
правкой и прогоном нужна пауза, иначе инверсия проверяет прежний код.

## 2. Скил учит неверному признаку — и по нему написан действующий тест

`vue-rules.md`, питфолл #64, приводил счётчик страниц «26-50 of 179» как признак
отрисованной страницы. Это неверно: `showingFrom`/`showingTo` в `usePagination.ts:12-13`
считаются из ЛОКАЛЬНОГО `page`, а не из ответа сервера.

Замер, снимки после клика «вперёд»:

```
T+   0мс  счётчик «11-20 из 100»  первая строка INV-2025-046  (СТАРАЯ)
T+ 100мс  счётчик «11-20 из 100»  первая строка INV-2025-046  (СТАРАЯ)
T+ 300мс  счётчик «11-20 из 100»  первая строка INV-2025-097  (новая)
```

Ожидание по счётчику возвращается со старыми строками — ловушка #64, замаскированная под
её же решение.

По этому совету написан `warehouse.spec.ts:273-277` — тест «every movement type is a
label». Он читает подписи ПРЕДЫДУЩЕЙ страницы, и последняя может не попасть в набор вовсе:
ровно та болезнь, о которой предупреждает его собственный комментарий двумя строками выше.

Чужой тест **не чинен молча** — заведён баг
[`pagination-counter-is-not-a-data-signal.md`](../../plans/bugs/pagination-counter-is-not-a-data-signal.md).
Скил исправлен: пример заменён, добавлено различие «величина из локального состояния» против
«величины из ответа» и предупреждение про `toHaveText` против `innerText()`.
