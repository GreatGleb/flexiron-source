# Прогон контракта: домен auth

Задача: привести уже написанный `roo-context/api/auth.md` в соответствие с
`00-conventions.md` и со своим аудитом (`plans/api/audit/auth.md`). Не переписывать заново.
Ветка `auto/contract-2026-09-04`, автономный режим. Код не тронут.

Входные числа аудита: эндпоинтов 5, источник истины «бэкенд» у 4, решений владельцу 10,
находок про код 15.

## Что изменено в контракте

1. **Общие правила заменены ссылками.** Ссылка на `00-conventions.md` из «появится в фазе B»
   стала настоящей; блок «сессия живёт не в cookie» (дословная копия §5) и общая часть
   «`id` — UUID» (§19) убраны, вместо них ссылки плюс домашний частный случай. Формы конверта
   ответа и разбор `detail` не переписаны — §1. Итого 11 ссылок на параграфы соглашений, ни
   одного второго экземпляра общего правила.
2. **Добавлено, чего не было:** «Каталог кодов ошибок домена» (7 кодов), «Обязанности сервера»
   (девять граф аудита), «Правила домена» (девять правил аудита), «Пробелы аудита — состояние».
3. **Устранены расхождения с кодом** — семь штук, все в разделе «Чего в домене нет» со строкой
   «что было описано и чем доказано отсутствие»: «logout идемпотентен», «logout инвалидирует
   сессию», «токен действителен до `expires_at`», «magic-link из письма», «срок в двух местах»
   (их три), «TTL назначает сервер через `expires_at`», «триал 14 дней».
4. **Формат:** пять разделов `### <МЕТОД> <путь>`, у каждого строка `Реализация:` и строка
   `Бэкенд:` (у `logout` — «не реализован»). Динамических сегментов у домена нет.
   `Статус: спроектировано` не поставлен ни разу: у всех пяти эндпоинтов код есть хотя бы на
   одной стороне. Упоминание метки в прозе раздела `logout` — вне якоря `^`, спека его не
   считает (`contractInventory.ts:238`), и печатает «спроектировано впрок: 0».

## Линзы К1–К7

### К1. Инвентарь: код ↔ контракт
**Чем:** `npx vitest run src/services/contract-conformance.spec.ts`, затем глазами правила
формата шага 3 — `grep -n '^### '`, `grep -c '^Реализация:'`, `grep -c '^Бэкенд:'`,
`grep -c '^### .*:'`.
**Что вернулось:** спека — 9 passed, 1 skipped; `сведено доменов: 2 · описано эндпоинтов: 6 из
175 · спроектировано впрок: 0`; ни одного пропущенного и ни одного лишнего эндпоинта у auth.
Заголовков `###` пять (строки 71, 142, 244, 281, 344), `Реализация:` — 5, `Бэкенд:` — 5,
заголовков с динамическим сегментом — 0. Инвентарь кода по домену:
`grep -rno "'/api/auth[a-z/]*'"` даёт ровно пять путей (login, register, me, logout, link).
**Вывод:** сходится. Пять на пять, у каждого обе обязательные строки.

### К2. Мок ↔ контракт ↔ код
**Чем:** скрипт, извлекающий ветки `path === '/api/auth/…'` из `mocks/index.ts` и вызовы
`'/api/auth/…'` из `useAuth.ts` и `AuthLinkHandler.vue`, с симметричной разностью в обе
стороны.
**Что вернулось:** ветки мока — link, login, logout, me (4, строки 296/303/875/905); вызовы
клиента — те же плюс register (5). **Дыра одна:** `/api/auth/register` — зовут, ветки нет
(БАГ-01). **Сирот нет.** Отдельно: ветка `logout` в моке недостижима, потому что клиент
выходит раньше (`useAuth.ts:225-229`) — в контракте это сказано.
**Вывод:** совпадает с замером аудита (1 дыра, 0 сирот); оба факта в контракте описаны.

### К3. Коды ошибок
**Чем:** три проверки. (а) инвентарь кодов бэкенда:
`grep -rhoE '"code": "[A-Z_]+"' backend/app | sort | uniq -c` и
`grep -rhoE 'code="[A-Z_]+"' backend/app/core/exceptions.py`; (б) коды мока:
`sed -n '294,310p;873,910p' mocks/index.ts | grep -oE "throw new Error\('[^']+'\)"`;
(в) подстрочность — попарное `a in b` по семи кодам каталога.
**Что вернулось:** бэкенд auth объявляет прямо в эндпоинте три — `MISSING_TOKEN`,
`TOKEN_EXPIRED`, `INVALID_TOKEN`; литеральных повторов кодов ядра по всему бэкенду
`NOT_FOUND` ×2, `UNAUTHORIZED` ×9, `VALIDATION_ERROR` ×2 — то есть три первых действительно
единственные вне каталога ядра. `FORBIDDEN` в модуле auth — 0 попаданий. Мок бросает
`MISSING_TOKEN` и два голых текста (`Not authenticated`, `Email and password are required`).
Подстрочность: ни одна пара из семи не вложена; **инверсия** — добавил в набор фиктивный
`TOKEN`, проверка нашла три вложения, значит она работает.
**Урок соседа применён** (журнал `contract-categories.md`, попытка 1): каждое утверждение об
отсутствии кода грепнуто по **всему** репозиторию, а не только по двум деревьям.
`INVALID_CREDENTIALS` — 3 файла, все документы (прежний контракт, аудит, сам контракт);
`EMAIL_TAKEN` — то же; в коде нет ни одного. Утверждения контракта сформулированы с областью
грепа и потому верны.
**Вывод:** каталог полон (7 кодов), происхождение каждого проверено, ни один не подстрока
другого.

### К4. Формы запроса и ответа
**Чем:** скрипт, вытаскивающий поля из pydantic-классов бэкенда, из `interface` в
`types/auth.ts` и из TS-блоков самого контракта, со сравнением трёх наборов; отдельно —
сравнение необязательности (дефолт на сервере против `?` во фронте).
**Что вернулось:** `UserInfo` (9 полей), `LoginResponse`, `RegisterResponse` (11 полей) —
бэкенд, фронт и контракт совпадают поле в поле. `MeResponse` = `UserInfo` + `secret_link`,
как и написано. `RegisterInput`: имена совпадают, **необязательность расходится ровно в двух
полях** — `first_name` и `last_name` объявлены `?` во фронте, а дефолта на сервере не имеют
(БАГ-04); `locale` и `phone` необязательны законно — у серверных есть дефолт.
**Находка этой линзы:** контракт (унаследовав формулировку аудита) называл слабым и `locale` —
неверно. Исправлено: названы два поля и рядом сказано, почему остальные два законны.
**Инверсия:** сравнил `MeResponse` с фронтовым `UserInfo` — проверка вернула `{secret_link}`,
то есть расхождение она видеть умеет.
**Вывод:** формы сведены, единственное расхождение — известное и записанное.

### К5. Источник истины

**Вывод:** источник назван по каждому эндпоинту, метка не поставлена там, где она была бы
