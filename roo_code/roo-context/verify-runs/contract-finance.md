# Прогон контракта: домен finance

## Попытка 1 — ОТКЛОНЕНА (2026-09-04)

Коммит попытки: `90c20cb` — откачен ревертом `69ecf5b`.

**Причина отклонения: контракт содержит ложное доказательство, выписанное в текст как
проверенный факт — напечатанная греп-команда с неверным выводом.**

### 1. Вывод напечатанной команды не воспроизводится

`roo_code/roo-context/api/finance.md:225` (раздел `GET /api/finance/payments`) утверждает:
«входящей записи в нём нет ни одной (`grep -c "direction: 'incoming'"
frontend_vue/src/services/mocks/finance.ts` → 0)». Та же команда из корня репозитория даёт
**1**, а не 0: попадание на `frontend_vue/src/services/mocks/finance.ts:72`, внутри
`receivables()`, где уведомление о просрочке отправляется с `direction: 'incoming'`.

Прозаическое утверждение («сид состоит из пяти outgoing») само по себе верно —
`grep -c "direction: 'outgoing'"` → 5. Неверен именно приведённый вывод, то есть в контракте
стоит непроверенное утверждение, выданное за проверенное — прямое нарушение Verification Rule
проекта. Одновременно оно скрывает настоящий факт домена: литерал `direction: 'incoming'` в
моке финансов ЕСТЬ, просто не в сиде, а в полезной нагрузке события — ровно того события,
вокруг которого построена графа 2 «Обязанности сервера». Читатель, перезапустивший
напечатанную команду, получит 1 и не сможет отличить, соврал контракт про сид или про грепу.

Линзы автора этого не поймали: К1 сверял формат заголовков, К7 — резолвимость ссылок, а
выводы напечатанных внутри текста греп-команд не пересчитывал никто. Из 22 греп-утверждений
контракта пересчитаны все 22 — 21 воспроизвелось точно, одно (это) нет.

### 2. Числа приёмки в сообщении коммита не восстанавливаются из коммита

В сообщении коммита заявлено «сведено доменов 4 · описано эндпоинтов 44 из 175». Четвёртый
домен — `roo_code/roo-context/api/orders.md` (149 КБ, 1643 строки), и он не в индексе и
никогда не коммитился: `git ls-files roo_code/roo-context/api/` возвращает только
`00-conventions.md`, `auth.md`, `finance.md`, `uploads.md`, а `git status --porcelain` —
`?? roo_code/roo-context/api/orders.md`. На чистом чекауте `90c20cb` спека увидит три домена,
а не четыре; дерево на момент коммита чистым не было, чего требует политика автономных
прогонов. Собственно финансовая часть числа («finance=5 ушёл из непокрытых») верна и от
`orders.md` не зависит.

### Что выдержало проверку

Приёмка зелёная, все пять разделов сходятся с кодом поле в поле, «Обязанности сервера» —
девять непустых граф с настоящими ссылками, два взятых из аудита утверждения подтвердились,
ни один пробел аудита не исчез молча, метки «спроектировано» нет нигде, удалённое из прежнего
контракта прослежено в «Чего в домене нет» построчно. Отклонение — по правилу «при любом
расхождении и при сомнении»: расхождение в доказательной базе.
