[`plans/api/audit/services.md`](../../plans/api/audit/services.md). Код не тронут: пять разделов

[`00-conventions.md`](../api/00-conventions.md).

### Свип линз К1–К7

**К1. Инвентарь: код ↔ контракт.** Чем: `npx vitest run src/services/contract-conformance.spec.ts`.
Вернулось: 9 passed, 1 skipped; `services` ушёл из строки «не сведено», описано 10 из 175
(5 auth + 5 services), пропущенных эндпоинтов домена — ноль. **Инверсия:** заголовок
`### DELETE /api/services/:id` временно заменён на `…/:id/archive` → спека покраснела **двумя**
утверждениями сразу («вызывается кодом, не описано в контракте» и «описано в контракте, в коде
нет»); файл возвращён и сверен побайтово (`diff -q` с копией — идентичен), спека снова зелёная.
Формат проверен глазами по шагу 3: динамический сегмент нигде не развёрнут в заголовки, примеры
не оформлены `###`, `:id` — один раздел на метод.

**К2. Мок ↔ контракт ↔ код.** Чем:
`grep -n "'/api/services'\|/\^\\\/api\\\/services" frontend_vue/src/services/mocks/index.ts`
плюс подсчёт вызывающих у каждого экспорта клиента. Вернулось: **пять ветвей мока на пять
эндпоинтов** — `:454` (GET список), `:467` (GET карточка), `:957` (POST), `:1238` (PATCH),
`:1511` (DELETE); вызывающих вне клиента: `getServices` 4, `getService` 6, `createService` 2,
`patchService` 3, `deleteService` 6. Ни дыры (описан — ветки нет), ни сироты (ветка есть —
вызывающего нет). Реестр «Клиент написан, UI нет» пуст обоснованно.

**К3. Коды ошибок.** Чем: `grep -rn "throw new Error('" mocks/services.ts` + строка
`mocks/index.ts:1518` + подстрочная проверка питоном + греп по **всему** репозиторию на каждое
утверждение об отсутствии (урок отклонённой попытки `categories`). Вернулось: домен бросает
ровно три кода — `SERVICE_CURRENCY_NOT_FOUND` (`:88`), `SERVICE_UOM_NOT_FOUND` (`:91`),
`CATALOG_SERVICE_NOT_FOUND` (`:134`, `:151`, ветка `index.ts:1518`); все три в каталоге раздела;
ни один не подстрока другого. **Инверсия подстрочности:** `'SERVICE_NOT_FOUND' in
'CATALOG_SERVICE_NOT_FOUND'` → `True`, то есть проверка умеет краснеть, и именно из-за этого
имя выбрано таким (`mocks/orders.ts:373-375`).

Два утверждения об отсутствии перепроверены по всему дереву и **из-за них правился текст**:

- `SERVICE_NOT_FOUND` — `grep -rn "'SERVICE_NOT_FOUND'" frontend_vue/src backend/app` даёт одно
  попадание, и это `toContain` в спеке заказов
  (`mocks/order-audit-authority-2.spec.ts:280`), а не `throw`. Формулировка усилена до «не
  бросает никто» с этой ссылкой;
- `VALIDATION_ERROR` — код **существует** как код ядра (`backend/app/core/exceptions.py:27`, и
  он же в таблице §2 соглашений). Первая формулировка строки «Чего в домене нет» читалась как
  утверждение об отсутствии кода — ровно та ловушка, на которой отклонили `categories`.
  Переписано: снята не существование кода, а доменная проверка, которая его бросала бы
  (в услугах кода нет ни в одной строке — греп в тексте строки).

До человека внутри домена не доходит ни один код: три общих тоста
(`useServices.ts:46`, `useServiceCard.ts:87`, `ServicesPage.vue:106`). Единственная трансляция —
словарь заказов (`orderLineEdits.ts:361`), и это записано в разделе.

**К4. Формы запроса и ответа.** Чем: питон-сравнение полей `interface Service` в
`types/service.ts` с блоком в контракте + греп колонок модели бэкенда. Вернулось: девять полей,
списки **совпали посимвольно и по порядку**; `description` объявлен необязательным, а не
обнуляемым (`types/service.ts:28`), и контракт говорит то же. **Инверсии (две, обе покраснели):**
подмена `sellingPrice` на снятое `priceUnit` → расхождение; потеря `updatedAt` → расхождение.
Со схемой сверено отдельно: колонки модели — `tenant_id`, `name_translations`, `cost_price`,
`selling_price`, `price_unit`, `description_translations`; `currency_id`/`uom_id` нет вовсе — это
БАГ-01, и он вынесен врезкой в начало раздела как запрет писать слайсы до миграции. Заодно
отмечено, что переводимые поля у этого домена на схеме **уже** `JSONB`, то есть услуги —
исключение из §12.

**К5. Источник истины.** Чем: подсчёт разделов и служебных строк грепом. Вернулось: разделов
эндпоинтов **5**, строк `Бэкенд: ` **5** (все — «не реализован»), строк `Реализация: ` **5**,
метка `Статус: спроектировано` — **0** попаданий (и это правильно: код у домена есть, нет только
серверной половины). Удалённое из прежнего контракта не пропало: 18 строк таблицы «Чего в домене
нет», каждая со ссылкой на строку `03-api-contract.md` и на то, чем опровергнута.

**К6. Обязанности сервера.** Чем: `awk` по разделу + подсчёт граф. Вернулось: **девять** граф,
ни одной пустой, у каждой `файл:строка`. Строки «нигде» не назначены, а сведены в раздел «Что
осталось нерешённым» — восемь пунктов, семь из них уже стоят в
[`00-решения-владельца.md`](../../plans/api/audit/00-решения-владельца.md) (строки 181–187),
восьмой — форма провода при стирании поля, зависящая от БАГ-06.

**К7. Ссылки и следы реализации.** Чем: скрипт из 105 проверок «токен внутри диапазона» —
каждая инлайновая ссылка контракта резолвится не существованием файла, а утверждаемым словом в
названных строках; плюс резолв всех относительных путей по файловой системе и всех 17 якорей
`00-conventions.md#…` против настоящих заголовков соседа. Вернулось: **105 сошлось, 0 провалов**;
11 относительных ссылок существуют, несовпавших якорей нет. **Инверсии (пять):** неверный
диапазон `models.py:22-27` для `EUR/vnt` → 0; `orders.ts:380-390` для `CATALOGUE_LANGUAGE` → 0;
`03-api-contract.md:1300-1310` для `SERVICE_IN_USE` → 0; `router/index.ts:260-270` для
`adminServices` → 0; `servicePricing.spec.ts` целиком для `CATALOG_SERVICE_NOT_FOUND` → 0.

Первый прогон К7 дал **20 провалов**, и все двадцать были в моём тексте, а не в коде:

- девятнадцать — сбитая нумерация ссылок на `03-api-contract.md`: я считал строки от смещения
  `sed -n '1140,1250p'` вместо `grep -n`, и весь блок ушёл на 1–2 строки (`SERVICE_NOT_FOUND`
  `:1140`→`:1142`, query `:1155-1157`→`:1157-1159`, `Feature Flags` `:1258`→`:1257` и так далее);
  плюс пара `description`/`createdAt` оказалась **перевёрнута** (`:1221` — это `description`,
  `:1222` — `createdAt`), то есть привязка внутри пары, на которой отклонили `categories`;
- одно — унаследованная из аудита неточность: аудит утверждает, что «все три кода проверены
  спекой (`servicePricing.spec.ts:94-108`)». В спеке домена `CATALOG_SERVICE_NOT_FOUND` нет
  вовсе (`grep -c` → 0); закреплены два кода из трёх, оба на пути правки (`:102-107`). В
  контракте написано так, как есть.
