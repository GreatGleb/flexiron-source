### К7. Ссылки и следы реализации

Три разных проверки, потому что ссылки в файле трёх видов.

**(1) Строки `Реализация:` и `Бэкенд:`** — есть у всех восьми разделов (см. К5); файлы и символы
резолвятся, символы найдены грепом: `getSuppliers`, `getSupplier`, `patchSupplier`,
`patchSupplierStatus`, `createSupplier`, `deleteAuditEntry`, `exportSuppliersCsv`,
`getSupplierList` — все восемь в `frontend_vue/src/services/suppliersService.ts`; функции мока
`mockGetSuppliers`, `mockGetSupplier`, `mockPatchSupplier`, `mockUpdateSupplierStatus`,
`mockDeleteAuditEntry`, `mockCreateSupplier`, `mockExportSuppliersCsv` — в
`frontend_vue/src/services/mocks/suppliers.ts`.

**(2) Относительные ссылки-документы** — резолвом по файловой системе от каталога файла:

```
ссылок-документов: 12 битых: 0
```

Все двенадцать: `00-conventions.md`, аудит, баг-файл, файл решений (трижды) и пять исходников
через `../../../frontend_vue/...`.

**(3) Инлайновые `файл:строка`** — их в разы больше, и именно на них держатся «Обязанности
сервера». Проверял двумя проходами.

Проход А — резолв всех ссылок скриптом (файл существует, диапазон внутри файла):

```

БИТЫХ: 0
```

Проход Б — **утверждаемый токен внутри диапазона**, потому что существования файла недостаточно:
181 пара «диапазон → токен, который контракт про него утверждает» (например
`models.py:50-52` → `server_default="EUR"`, `mocks/suppliers.ts:521` → строка заголовка CSV,
`mocks/index.ts:327-330` → `s.company.en`, `useDirtyCheck.ts:62-77` → `JSON.stringify`):

```
проверено утверждений: 181 · провалов: 0
```

Первый прогон дал 7 провалов, и **три из них были настоящими ошибками ссылок**, а не ошибками
теста:

- `WarehousePage.vue:525` цитировался как место, где отказ справочника гасится в `catch`. На
  `:525` лежит сам вызов `getSupplierList()`, а `} catch {` — на `:530`. Исправлено: вызов
  `:525`, гашение `:530-531`. Ссылка пришла из аудита в этом виде и была бы принята на глаз;
- та же строка `:519` в перечне потребителей указывала на `import`, а не на вызов, — уточнено
  («`:525`, импорт — `:519`»);

Остальные четыре провала были дефектами самого теста (переэкранированный регэксп, ожидание

дельты) — исправлены ожидания, не контракт.

**Инверсия обязательна и здесь.** Оба скрипта сломаны нарочно и покраснели именно на том, что
сломано:

### Пробелы аудита

Тридцать пробелов, перечисленных аудитом по восьми эндпоинтам, разошлись так:

- **девять закрыты в тексте** правилом старшинства (у эндпоинта нет бэкенда → истина у мока и
  клиента) или общим соглашением: поля поиска `search`; отсутствие эндпоинта `/list` в прежнем
  контракте; плоская строка `company` в справочнике; форма `text/csv` на проводе (неспособность
  клиента её прочитать — БАГ-04, находка про фронт); пересчёт `updatedAt` сервером (§14,
  `backend/app/core/base.py:25-37`); свободная строка `notes` без формата блоков; правило
  переходов статуса, сохранённое как замысел с прямым указанием, что кодом оно не выражено;
  расхождение списка и карточки (правило домена 6 + БАГ-03); удаление записи аудита без
  мета-записи;
- **двадцать один помечен «осталось»** со ссылкой на строку владельца: форма id (трижды), рейтинг
  как минимум или равенство, сортировка списка, справочный `pageSize: 999`, вырезание полей по
  правам, второй журнал `history`, склейка `priceHistory`, набор колонок и объём экспорта,
  `fileIds` против `files`, формат `oldValue`/`newValue`, запись аудита сервером (дважды),
  дефолты и владельцы трёх справочников, право `create`, `If-Match` и `Idempotency-Key`, связь
  `statusReason` со сменой статуса, уникальность `entryId`. Ни одно из них контракт не назначает:
  наблюдение записано, решение — владельцу.

Проверено машинно: пометок «осталось» в файле 32 вхождения (часть граф ссылается на одну строку
владельца дважды — из раздела эндпоинта и из «Обязанностей сервера»).
