Почему PW_PORT в ядре, а не в адаптере aider: номер слота в пачке знает только ядро
(`batch_env`), а e2e в worktree запускают авторы любого исполнителя. Checks ядра и
приёмка идут последовательно в checkout и порта не получают — сталкиваться им не с кем.

Как ведётся пачка (прочитано в `run`): авторы пачки — `ThreadPoolExecutor`, ядро ждёт ВСЕХ
(`as_completed`), затем по одной задаче `git apply` → `npm run verify` + checks → приёмка →
коммит. Параллельна только фаза авторов, самый медленный автор держит пачку.

5б жил с рождения параллельного режима: проверки ядра идут в checkout, где node_modules
настоящие, и дефекта не видели; видел его только автор — как ложный красный e2e.
