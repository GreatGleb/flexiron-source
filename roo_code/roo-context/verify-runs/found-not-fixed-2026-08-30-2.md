## Итерация 1 — перепись, а не оценка на глаз

Счёт плана — 123 — считал только строковые литералы. Полная перепись формой
`await page.goto(<'/admin/orders…' | шаблон>)`:

| форма | сколько | был ли пол |
|---|---|---|
| `goto` + `waitForSelector(sel)` | 62 | нет |
| `goto` + `expect(page.locator(sel)).toBeVisible()` | 34 | нет |
| `goto` + комментарий + `waitForDataReady(page)` | 14 | **да** |
| `goto` + `waitForDataReady(page)` | 2 | **да** |
| `goto` + собственное ожидание ниже по телу | 13 | нет |
| **всего** | **125** | без пола — **109** |

Два перехода — шаблонные литералы (`/admin/orders/${orderId}`), в счёт 123 они не попадали.

## Правка

- 96 мест (`waitForSelector` и `toBeVisible`) свёрнуты в `openAdminPage(page, URL, sel)` —
  тот же маркер, что стоял, плюс пол `waitForDataReady`;
- 29 мест — `navigateToAdmin(page, URL)`; собственное ожидание теста остаётся потолком;
- удалены 12 копий одного и того же комментария «Переход и сразу действие: без этого
  ожидания тест зависит от того, успела ли страница подняться» — это Л5: правило, записанное
  двенадцать раз рядом с вызовом, который его и означает. Два содержательных комментария
  (про сторож `initialized`, питфолл #20) сохранены;
- импорт `waitForDataReady` стал не нужен и убран.

**Почему не `openAdminCard`, как просил план.** `openAdminCard` ждёт непустое ЗНАЧЕНИЕ поля
ввода (`not.toHaveValue('')`). Из 125 переходов 11 ведут на список `/admin/orders` и 19 —
на `/admin/orders/new`, где такого поля нет вовсе; на карточке подходящее поле есть
(`field-gross-total` — это `input` с `v-model="grossInput"`), но единый маркер для трёх
разных видов страниц из него не получается. Взят тот признак, который у каждого места уже
был, и добавлен пол, которого не было.

## Итерация 2 — доказательство инверсией (Л9)

Не «стало зелено»: зелёным было и до правки. Доказывается падение СТАРОГО ожидания под
`Emulation.setCPUThrottlingRate` (CDP, rate 40, один воркер) — задержка растягивается
детерминированно. Оба варианта одного теста рядом, во временном спеке (удалён):

| вариант | итог |
|---|---|
| старый: `goto` + `expect(order-shipments).toBeVisible()` (потолок 5 с) | **failed**, `element(s) not found` |
| новый: `openAdminPage(page, …, order-shipments)` | passed |
| старый: `goto` + `waitForSelector(order-item-row)` (потолок 30 с) | passed |
| новый: `openAdminPage(page, …, order-item-row)` | passed |

Ошибка старого варианта — дословно та, что записана в баге по реальному падению.

**Третья строка объясняет, почему из 109 проявился ровно один.** Потолок `waitForSelector`
— 30 секунд, потолок `expect` — 5. Ждали неверно все 109; падал тот, кому не хватило
запаса. То есть «остальные 122 прикрыты» — правда только про запас времени, а не про
правильность ожидания, и держится она ровно до занятой машины.

## Итерация 3 — свип

| проверка | команда | результат |
|---|---|---|
| машинная приёмка | `npm run verify` | exit 0 · typecheck · lint · dupes · format · 751 unit |
| e2e, уровень 1 | `npx playwright test tests/e2e/admin/orders/ --workers=3` | exit 0 · **128 passed** (3.2 мин) |

Уровень 1, а не 2: правка в одном спеке, общего пола (`helpers/`, фикстуры, диспетчер
моков) не касается. Каталог заказов прогнан целиком — оба спека, `orders` и `order-offcuts`.

**Линзы.**

- **Л9** — инверсия проведена, таблица выше. Плюс машинная часть линзы:
  `grep -rn "await page.waitForLoadState" tests/` → 0;
- **Л5** — двенадцать копий одного комментария убраны, правило теперь живёт в одном месте
  (`helpers/admin.ts`). Проверено, что в файле не осталось ни одного голого перехода:
  `grep -c "page.goto(" tests/e2e/admin/orders/orders.spec.ts` → **0**;
- **Л1–Л4, Л6–Л8, Л10** — правка `src/` не касается вовсе, подтверждены зелёной приёмкой.
