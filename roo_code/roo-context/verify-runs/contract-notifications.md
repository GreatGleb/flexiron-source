# Прогон контракта: домен notifications

## Попытка 1 — ОТКЛОНЕНА (2026-09-04)

Коммит попытки: `6248aed` — откачен ревертом `a8634b9`.

**Причина отклонения: раздел «Чего в домене нет» ссылается на прежний контракт
(`03-api-contract.md`) мимо — три номера строк указывают не на то место, а линза К7
заявлена пройденной («177 пар → 0 не найдено»), хотя эти цитаты в проверяемое множество
не попадали.**

### Находка 1 — строка 547 контракта, адрес 2965

Цитата: «Возвращает количество непрочитанных уведомлений **для текущего пользователя**»
(со ссылкой на строки 2965, 2987). В `03-api-contract.md` строка 2965 — это «Лёгкий
endpoint — минимум нагрузки, без пагинации и фильтров.»; цитируемое предложение лежит
на **2963**. Утверждаемого токена по указанному адресу нет.

### Находка 2 — строка 550, адрес 2862

Цитата: «Уведомления генерируются сервером при событиях (… истечение резерва …)»
(строка 2862). Строка 2862 **пустая** (`sed -n '2862p' | cat -A` → `$`); предложение
лежит на **2863**.

### Находка 3 — строка 537, граница раздела 2860–2995

Заявлено: «раздел `# Admin — Notifications`, строки 2860–2995». Заголовок на **2861**,
следующий `# ` — на **3017**, то есть настоящий раздел 2861–3016. Объявленное окно короче
на 21 строку, и цитата последней строки самой таблицы («Никаких форм редактирования,
clean-slate не применим», строка 3000) лежит **вне** объявленного окна вместе с блоками
Save UX (2997–3000) и Feature Flags (3002–3006). По существу эти утверждения в тексте
разобраны, но заявленная граница «каждое утверждение раздела 2860–2995» не описывает
того, что проверялось.

### Почему это не придирка

Заявление автора «(3) УТВЕРЖДАЕМЫЙ ТОКЕН внутри диапазона — 177 пар, 0 не найдено; линза
пройдена» неполно. Скрипт автора ловил ссылки формата `файл:строка`, а цитаты в прежний
контракт написаны прозой («строка 2965», «строки 2860–2995») и в проверяемое множество
не попали — ровно там и оказались все ошибки. Независимый машинный проход по 128
уникальным `файл:строка` дал 0 выходов за границы и 0 битых markdown-ссылок из 12 — то
есть заявленная часть К7 верна, а незаявленная провалена. Читатель, пошедший по ссылке
2965 или 2862, опровергаемого утверждения не найдёт — тот же класс дефекта, который автор
в этом же прогоне сам чинил (`useNotifications.ts:98` → `:95`).

Следующей попытке: К7 обязана покрывать **прозаические** ссылки на номера строк
(«строка N», «строки N–M»), а не только пары `файл:строка`; границы разделов проверять
грепом заголовков, а не на глаз.

### След для следующего захода (не основание отклонения)

Сам аудит [`roo_code/plans/api/audit/notifications.md:43`](../../plans/api/audit/notifications.md)
и `00-решения-владельца.md` держат неверный `useNotifications.ts:98` для дефолта
`intervalMs = 30_000` — он на `:95`. Контракт эту ошибку исправил, но во входных файлах
она осталась.

### Что проверено и сошлось

Приёмка зелёная, все четыре раздела сверены с кодом и сошлись. Остальные семь проверок
задания прошли:

- разделов ровно 4, все формата `### МЕТОД /api/...`;
- формы запроса/ответа совпали с `types/notifications.ts` поле за полем (девять полей,
  восемь типов, пять сущностей);
- каталог кодов пуст и это доказано (единственный `throw` — тестовый рычаг,
  `NOTIFICATION_NOT_FOUND` пусто в обоих деревьях);
- «Обязанности сервера» — девять непустых граф, в каждой наблюдение с `файл:строка`,
  графа «кастомные поля» закрыта отрицательным грепом;
- все 16 пробелов аудита в таблице, шесть помечены «осталось»;
- метки `Статус: спроектировано` нет ни одной — и это правильно, клиент зовёт все четыре
  пути;
- удалённое из старого контракта следы оставило (11 строк с опровержениями).

**Итог:** дефект локальный — три номера строк и одна граница диапазона. По правилу «хоть
одно расхождение — refuted» домен отклонён целиком.
