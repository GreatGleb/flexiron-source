**К3. Коды ошибок.**

Что бросает мок домена — `grep -n "throw new Error"` по `mocks/clients.ts` (14 попаданий) и по
веткам clients в `mocks/index.ts` (одно, `:521`). Различных кодов **пять**:

`useClients.ts:63-76` плюс три языка ключа (`i18n/admin/clients.ts:57`, `:186`, `:316`).

**Подстрочность.** Единственное подстрочное сравнение домена —
`grep -rn "includes('CONFLICT'…" src` → `useClients.ts:70`. Проверил, есть ли чужой код, который
оно поймает:

```
grep -rhoE "[A-Z][A-Z_]*CONFLICT[A-Z_]*" src --include=*.ts --include=*.vue | sort -u
→ ORDER_VERSION_CONFLICT
grep -rhoE "[A-Z][A-Z_]*AUDIT_ENTRY_NOT_FOUND" …
→ ORDER_AUDIT_ENTRY_NOT_FOUND
```

То есть `CONFLICT` — подстрока живого кода `ORDER_VERSION_CONFLICT`, и сравнение стоит ровно на
той строке, где это важно. Сегодня коллизия не срабатывает (удаление клиента версию не
проверяет), но правило §2 общих соглашений нарушено. **Дедуплицировано:** ключ находки
`useClients.ts:handleDelete:чтение кода ошибки` совпадает с БАГ-02 — дописано абзацем внутрь
БАГ-02, новой записи не создано.

**Инлайновые `файл:строка` — скриптом, все за один проход.** Скрипт резолвит сокращённые пути
(`mocks/…`, `types/…`, `composables/…`, голый basename) и продолжения вида `:1234`, а затем
проверяет не существование файла, а **утверждаемый токен внутри диапазона**: берёт бэктиковые
идентификаторы из фрагмента строки, относящегося именно к этой ссылке, и требует попадания хотя бы
одного в вырезанный `sed`-ом кусок.

```
ссылок: 239 · OK (токен найден): 62 · NOTOKEN (утверждаемого токена нет): 153 · MISS: 24 · битых: 0
```
