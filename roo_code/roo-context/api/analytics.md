# Analytics

Восемь отчётных страниц админки: дашборд руководителя, склад, продажи, закупки, сотрудники,
логистика, P&L и дефицит. Общие соглашения — конверт ответа, коды ядра, мультиарендность,
заголовки, `TranslatedString`, даты и деньги, производные значения — в
[`00-conventions.md`](00-conventions.md); здесь только то, что живёт в этом домене.

**Источник истины — мок и клиент** (ступень 2 старшинства). Модуля `analytics` на бэкенде нет
вовсе — не «есть, но без роутов», как у `warehouse` или `notifications`, а нет каталога: в
`backend/app/modules/` десять модулей — `auth`, `bcc`, `billing`, `finance`, `notifications`,
`products`, `services`, `settings`, `suppliers`, `warehouse`, — и `analytics` среди них нет
(`ls -d backend/app/modules/analytics` → `No such file or directory`). Ни модели, ни таблицы, ни
миграции: `grep -rn "analytic" backend/
--include=*.py` даёт два попадания, и оба — текст описания фичи в сид-миграции
([`8cf3bfa380dd_phase_12_plans_multi_role.py:28,34`](../../../backend/alembic/versions/8cf3bfa380dd_phase_12_plans_multi_role.py)),
то есть слово в переводе, а не код. Прежний
[`03-api-contract.md:694-743`](../03-api-contract.md) старше кода по времени и расходится с ним в
шести местах — что именно снято, перечислено в разделе «Чего в домене нет».

Потребители — восемь страниц в
[`views/admin/analytics/`](../../../frontend_vue/src/views/admin/analytics) через один композабл
[`composables/useAnalytics.ts`](../../../frontend_vue/src/composables/useAnalytics.ts) и один
сервис [`services/analyticsService.ts`](../../../frontend_vue/src/services/analyticsService.ts) на
шесть строк.

**Домен ничего не хранит, и это его главное свойство.** Своих таблиц у него нет, все 19 массивов
ответа — производные от чужих сущностей (склад, заказы, поставщики, финансы, пользователи).
Поэтому самая нагруженная часть этого файла не форма ответа, а раздел «Обязанности сервера»,
графа «Производные значения»: там сказано, что сервер обязан посчитать и из чего, — и там же
видно, что для двух страниц из восьми считать **не из чего**, потому что исходных сущностей нет
ни во фронте, ни на сервере.

**Домен read-only целиком.** Ни одной записи:
`grep -c "apiPost\|apiPut\|apiPatch\|apiDelete\|apiUpload" src/services/analyticsService.ts` → `0`.
Во всём домене один вызов, и он `GET`. Save-режима нет ни у одной страницы, `Idempotency-Key` и
`If-Match` не применимы по составу домена.

### GET /api/analytics/:page

Отдаёт данные одной отчётной страницы. Один эндпоинт на все восемь: `:page` — литерал из
замкнутого союза `AnalyticsPageKey`
([`types/analytics.ts:3-11`](../../../frontend_vue/src/types/analytics.ts)), восемь значений:

| `:page` | страница-потребитель | какие поля непусты (замер по моку) |
|---|---|---|
| `dashboard` | `DashboardPage.vue:11` | `kpis` (5), `salesByCategory` (5), `alerts` (5), `sectionPreviews` (7) — `mocks/analytics.ts:243-248` |
| `warehouse` | `WarehousePage.vue:8` | `kpis` (4), `deadstock` (5), `turnover` (5) — `mocks/analytics.ts:365-372` |
| `sales` | `SalesPage.vue:8` | `kpis` (4), `topClients` (5), `refusalReasons` (3) — `mocks/analytics.ts:462-469` |
| `supply` | `SupplyPage.vue:8` | `kpis` (4), `suppliers` (4), `supplyCategories` (4) — `mocks/analytics.ts:578-585` |
| `staff` | `StaffPage.vue:8` | `kpis` **пуст**, `managers` (4), `workers` (3), `revenues` (4) — `mocks/analytics.ts:670-678` |
| `logistics` | `LogisticsPage.vue:8` | `kpis` (4), `routes` (5), `loads` (4) — `mocks/analytics.ts:795-802` |
| `pl-report` | `PlReportPage.vue:10` | `kpis` **пуст**, `plRows` (10, из них 3 разделителя), `calendarEvents` (6) — `mocks/analytics.ts:877-884` |
| `deficit` | `DeficitPage.vue:8` | `kpis` (4), `deficitItems` (5), `refusalVolumes` (5) — `mocks/analytics.ts:1007-1014` |

Save-режим: **нет, домен read-only.** Загрузка разовая и без кеша — `load()` стоит прямо в теле
`<script setup>`, а не в `onMounted` (`DashboardPage.vue:12`, `WarehousePage.vue:9`,
`SalesPage.vue:9`, `SupplyPage.vue:9`, `StaffPage.vue:9`, `LogisticsPage.vue:9`,
`PlReportPage.vue:11`, `DeficitPage.vue:9`), а состояние композабл создаёт заново на каждый вызов
(`useAnalytics.ts:7-9`). Значит каждый переход по вкладкам подшивки
([`AnalyticsSubNav.vue:9-18`](../../../frontend_vue/src/components/admin/AnalyticsSubNav.vue)) —
новый полный запрос; повторного использования ответа нет нигде.

Запрос: **только сегмент пути.** Ни одного query-параметра и ни одного заголовка — клиент зовёт
`apiGet` без второго и третьего аргументов (`analyticsService.ts:5`), а `options?.headers` —
единственный источник заголовков у `GET`
([`services/api.ts:157-159`](../../../frontend_vue/src/services/api.ts)).
`grep -c "Idempotency\|Authorization\|authHeaders" src/services/analyticsService.ts` → `0`; про
отсутствие `Authorization` — БАГ-02, про арендатора — графа «Мультиарендность».

Ответ: `ApiResponse<DashboardData>` — конверт снимает `unwrap()` (`services/api.ts:127-138`), тип
объявлен `types/analytics.ts:216-251`. **Один shape на все восемь значений `page`, дискриминации
нет** — так решено осознанно, и это единственное утверждение прежнего контракта о форме, которое
код подтвердил (`03-api-contract.md:700`).

```ts
interface DashboardData {
  // обязательные — четыре, приходят всегда
  kpis: KpiItem[]
  salesByCategory: ChartBarItem[]
  alerts: AlertItem[]
  sectionPreviews: AnalyticsSectionPreview[]
  // необязательные — пятнадцать, по два-три на страницу
  deadstock?: DeadstockItem[]          // warehouse
  turnover?: TurnoverItem[]            // warehouse
  topClients?: TopClientItem[]         // sales
  refusalReasons?: RefusalReasonItem[] // sales
  suppliers?: SupplierItem[]           // supply
  supplyCategories?: SupplyCategoryItem[] // supply
  managers?: ManagerItem[]             // staff
  workers?: WorkerItem[]               // staff
  revenues?: RevenueItem[]             // staff
  routes?: RouteItem[]                 // logistics
  loads?: LoadItem[]                   // logistics
  plRows?: PlRowItem[]                 // pl-report
  calendarEvents?: CalendarEvent[]     // pl-report
  deficitItems?: DeficitItem[]         // deficit
  refusalVolumes?: RefusalVolumeItem[] // deficit
}
```

Формы элементов — `types/analytics.ts:13-208`, по интерфейсу на массив; список замкнут типом, а
не соглашением.

**Правило пустоты асимметрично, и сервер обязан держать обе половины** (`types/analytics.ts:216-251`
против `mocks/analytics.ts:243-1014`):

- **четыре обязательных поля приходят всегда**, и страница, которой поле не принадлежит, получает
  `[]`, а не отсутствие ключа: `warehouseData` шлёт `salesByCategory: []`, `alerts: []`,
  `sectionPreviews: []` (`mocks/analytics.ts:365-372`), и так же остальные шесть не-дашбордных;
- **пятнадцать необязательных полей чужая страница не шлёт вовсе** — `dashboardData` состоит ровно
  из четырёх ключей (`mocks/analytics.ts:243-248`), пустых массивов на месте `deadstock` или
  `plRows` в нём нет.

**`kpis` — обязательное поле, которое две страницы из восьми присылают пустым**, и обе про это
знают: `staffData.kpis: []` (`mocks/analytics.ts:670-678`), `plReportData.kpis: []` (`:877-884`), а
шаблоны обёрнуты в `v-if="data?.kpis?.length"` (`StaffPage.vue:26`, `PlReportPage.vue:27`) —
единственные две из восьми; у остальных шести обёртки нет (`DashboardPage.vue:82`,
`WarehousePage.vue:35`, `SalesPage.vue:35`, `SupplyPage.vue:35`, `LogisticsPage.vue:35`,
`DeficitPage.vue:35`). То есть «пустой массив вместо отсутствия ключа» — действующее правило
домена, а не случайность мока.

**Числа приходят двумя несовместимыми способами, и это часть формы.** Уже отформатированной
строкой — `KpiItem.value: string` (`types/analytics.ts:16`, в моке `'127 400'`,
`mocks/analytics.ts:31`), `AnalyticsMetricItem.value` (`types/analytics.ts:56`),
`PlRowItem.value` (`:175`), `LoadItem.value` (`:167`), `DeficitItem.stock`/`min` (`:193-194`) — и
сырым числом: `ChartBarItem.value` (`:42`), `TopClientItem.value` (`:85`), `RevenueItem.value`
(`:145`), `RouteItem.revenue` (`:156`). Сырые числа фронт форматирует тремя разными способами, один
из них — по локали **браузера** (БАГ-05).

**Часть полей — не данные, а презентация, и её вокабуляр замкнут фронтендом.** Сервер обязан
присылать значения из этих наборов, потому что каждый из них индексирует карту в шаблоне:
`KpiItem.trend: 'up'|'down'|'neutral'` (`types/analytics.ts:26`) → CSS-класс
(`DashboardPage.vue:102`); `KpiItem.iconColor: 'blue'|'red'|'green'|'gold'`
(`types/analytics.ts:28`) → класс `icon-<цвет>` (`DashboardPage.vue:84`); `AlertItem.status`
(`types/analytics.ts:36`) → и класс пилюли, и ключ подписи (`DashboardPage.vue:27-42`); готовый
CSS-градиент несёт `color` у `TurnoverItem` (`types/analytics.ts:78`), `TopClientItem`
(`types/analytics.ts:87`), `RefusalReasonItem` (`types/analytics.ts:95`), `SupplyCategoryItem`
(`types/analytics.ts:115`), `RevenueItem` (`types/analytics.ts:147`), `LoadItem`
(`types/analytics.ts:168`) и `RefusalVolumeItem` (`types/analytics.ts:207`); класс пилюли —
`ageStatus` (`types/analytics.ts:68`), `statusType` (`types/analytics.ts:106`, `:159`, `:198`),
`ratingType` (`types/analytics.ts:127`) и `errorType` (`types/analytics.ts:138`).

**Четыре ключа сервер обязан знать буквально** — правило домена №4 ниже.

Все человекочитаемые строки — `TranslatedString` (`{ru,en,lt}`,
[`types/i18n.ts:6-10`](../../../frontend_vue/src/types/i18n.ts)): сервер отдаёт все три языка
сразу, локаль выбирает клиент через `tf()`
([`useTranslatedData.ts:26-32`](../../../frontend_vue/src/composables/useTranslatedData.ts)) —
перезапроса при смене языка нет. В моке заполнены все три без исключений (по 164 попадания
`ru: '`, `en: '`, `lt: '` плюс шесть многострочных блоков с тем же балансом). Общее правило и
выбор помощника слияния — `00-conventions.md`, §12.

Ошибки: **каталог домена пуст** — см. раздел ниже.

Бэкенд: **не реализован** — модуля `analytics` в `backend/app/modules/` нет вовсе, поэтому у
домена нет ни роута, ни схемы, ни таблицы. Для сервера этот раздел целиком задание, а не описание
существующего; метки `Статус: спроектировано` он при этом не несёт — код домена **есть**, просто
весь во фронте (клиент, мок, восемь страниц).

Реализация: `services/analyticsService.ts:4-5` (`getAnalyticsPage`) · композабл
`composables/useAnalytics.ts:12` (`load`) · мок-ветка `mocks/index.ts:310-312` → резолвер
`mocks/analytics.ts:1018` (`mockGetAnalyticsPage`)

## Каталог кодов ошибок домена

**Пуст, и это измеренный факт, а не пропуск.** Мок не бросает ничего:
`grep -c "throw" src/services/mocks/analytics.ts` → `0`, ветка `mocks/index.ts:310-312` тоже без
бросков. Бэкенда у домена нет, поэтому и пять кодов ядра
([`core/exceptions.py:13-48`](../../../backend/app/core/exceptions.py), перечень — `00-conventions.md`
§2) домен не наследует ни одного: наследовать некуда.

Два следствия, которые сервер обязан закрыть, потому что сегодня их не закрывает никто:

- **неизвестное значение `page` даёт `200` с валидным пустым ответом**, а не отказ:
  `default` резолвера возвращает четыре пустых массива (`mocks/analytics.ts:1036-1042`), а ветка
  разбора ловит регуляркой `/^\/api\/analytics\/(.+)$/` (`mocks/index.ts:310`) — то есть любой
  хвост, включая слэши. Фронт при этом рисует пустую страницу без сообщения. БАГ-07;
- **путь ошибки во фронте есть, но безымянный:** `catch` кладёт `e.message`
  (`useAnalytics.ts:17-19`), и восемь страниц печатают его сырым —
  `<div v-else-if="error" class="error-state">{{ error }}</div>` (`DashboardPage.vue:79`,
  `WarehousePage.vue:33`, `SalesPage.vue:33`, `SupplyPage.vue:33`, `StaffPage.vue:24`,
  `LogisticsPage.vue:33`, `PlReportPage.vue:25`, `DeficitPage.vue:33`). Ни кода, ни перевода, ни
  `data-test`, ни стиля. БАГ-09.

Правило «отказ несёт код, а не текст» — `00-conventions.md`, §2; здесь оно нарушено в обе стороны:
кода нет ни у одной ошибки домена, а текст доезжает до человека буквально.

**Осталось:** строка 12 — какой код и какой статус несёт неизвестное значение `page`, и чем
«страницы нет» отличается от «данных нет». Придумать код здесь нельзя: ни мок, ни бэкенд такого
кода не знают, а порядок старшинства запрещает назначать поведение вместо владельца.

Находки про код собраны в
[`contract-sync-analytics-bugs.md`](../../plans/bugs/contract-sync-analytics-bugs.md) — девять
штук, код не тронут.

## Правила домена

Шесть правил, каждое живёт только в этом домене и ни в одном другом.

**1. Период отчёта не передаётся, не возвращается и подписан переводом.** Ни запрос
(`analyticsService.ts:5` — параметров нет), ни ответ периода не знают: во всём файле типов нет ни
отметки времени, ни границ интервала — `grep -c "asOf\|generatedAt\|timestamp"
src/types/analytics.ts` → `0`, и ни одно из девятнадцати полей `DashboardData`
(`types/analytics.ts:216-251`) даты не несёт. При этом на экране период показан — и взят из
словаря переводов: `badge_march: 'Март 2026'` повторён 21 раз, по семь секций в каждой из трёх
локалей ([`i18n/admin/analytics.ts:15,50,67,86,118,141,190`](../../../frontend_vue/src/i18n/admin/analytics.ts),
`:215,250,267,286,318,341,390`, `:415,450,467,486,518,541,590`), плюс `badge_april`, `badge_q1`,
`badge_today`; рендерится как `t('dashboard.badge_march')` (`DashboardPage.vue:111`) и ещё в
шестнадцати местах (`grep -n "badge_" src/views/admin/analytics/*.vue` → 17). Смена месяца сегодня
требует правки словаря на трёх языках. **И в подписи периода спрятаны данные:**
`badge_deals: '29 сделок'` (`i18n/admin/analytics.ts:51`, `'29 deals'` `:251`,
`'29 sandoriai'` `:451`) — число из отчёта, живущее в файле переводов (БАГ-08).
**Решено 2026-09-07 (П27):** период считает сервер — **текущий месяц, с 1-го числа по текущий момент**; клиент его не задаёт. Мок обязан всегда показывать текущий месяц и год, а не зашитый `badge_march: 'Март 2026'`, повторённый 21 раз по семи секциям трёх локалей.

**2. Валюта и единицы измерения — константы перевода, а не справочник арендатора.** Подробности с
ссылками — в графе «Значения по умолчанию»; правило домена в том, что **отчёт нельзя показать
арендатору с другой валютой, не тронув `i18n/admin/analytics.ts` и три шаблона.** Общее правило
«справочник принадлежит серверу, копии во фронте быть не должно» — `00-conventions.md`, §14.
**Осталось:** решение владельца, строка 2.

**3. Поле `percentage` означает разное в соседних полях одного ответа.** В `refusalReasons` это
доля от целого: 62 + 28 + 10 = 100 (`mocks/analytics.ts:452-460`). В `salesByCategory` — нет:
78 + 55 + 38 + 20 + 12 = 203, и это не доля от максимума тоже (у максимума 78, а не 100)
(`:80-86`). В `topClients` — 88 + 62 + 45 + 30 + 19 = 244 (`:419-450`). Потребитель во всех
случаях один — ширина полосы: `width: item.percentage + '%'` (`DashboardPage.vue:125`) и то же
выражение с другим именем строки — `width: client.percentage + '%'` и
`width: reason.percentage + '%'` (`SalesPage.vue:76,104`), `StaffPage.vue:112`,
`LogisticsPage.vue:107`, `SupplyPage.vue:111`, `DeficitPage.vue:109`, — то есть фронту всё равно,
а серверу нужно правило. Проверяемое
следствие: в `salesByCategory` сумма `value` равна KPI «Выручка (мес.) 84 200»
(`mocks/analytics.ts:80-86`: 32400 + 22800 + 15900 + 8200 + 4900 = 84200), то есть настоящая доля
там — `value`, а `percentage` рядом с ней — нет. БАГ-06.
**Осталось:** правило вычисления `percentage` — решение владельца, строка 3.

**4. Четыре семейства ключей сервер обязан знать буквально, потому что фронт ими индексирует свои
словари.** Все четыре замкнуты кодом фронта, а не схемой:

| поле | чем индексирует | что при промахе |
|---|---|---|
| `KpiItem.unit` | ключ i18n, рендерится `t(kpi.unit)` (`types/analytics.ts:17-24`, `DashboardPage.vue:100`) | `t()` печатает сам ключ |
| `AnalyticsSectionPreview.key` | одновременно сегмент маршрута `'/admin/analytics/' + section.key` и ключ подписи `t('sub.' + section.key)` (`DashboardPage.vue:173,176`) | битая ссылка и ключ вместо подписи |
| `KpiItem.icon` | карта из пяти путей SVG (`DashboardPage.vue:15-24`) | `kpiIconPaths[kpi.icon] ?? ''` рисует пустой путь (`:95`) |
| `AlertItem.status` | карта классов пилюли и карта ключей подписи (`DashboardPage.vue:27-42`) | пилюля без класса, ключ вместо текста |

Промах у всех четырёх тихий, и один уже есть в коде: мок шлёт `sectionPreviews` с ключом
`'pl-report'` (`mocks/analytics.ts:226`), а в словаре подписей ключ называется `pl`
([`i18n/admin/layout.ts:22`](../../../frontend_vue/src/i18n/admin/layout.ts), `:80`, `:138`) — та
же подшивка вкладок зовёт его `sub.pl` (`AnalyticsSubNav.vue:16`). Карточка P&L на дашборде
печатает сам ключ. БАГ-01.

По `unit` набор замерен и сходится: мок шлёт 15 ключей в шести пространствах имён
(`dashboard`, `warehouse`, `sales`, `supply`, `logistics`, `deficit`), и все 15 существуют во всех
трёх локалях. По `icon` — не сходится: мок шлёт десять имён (`alert`, `chart-bar`, `check`,
`clock`, `currency`, `package`, `receipt`, `trending-up`, `truck`, `users`), карта знает пять
(`DashboardPage.vue:15-24`), а читает поле одна страница из восьми (БАГ-04).
**Осталось:** остаётся ли `icon` в контракте и каков его замкнутый набор — решение владельца,
строка 13.

**5. Восемь страниц — восемь запросов, кеша нет ни на одном уровне.** `useAnalytics` создаёт
состояние заново на каждый вызов (`useAnalytics.ts:7-9`), `load()` стоит в теле `<script setup>`
восьми страниц (ссылки в разделе эндпоинта), общего стора нет. Проход по восьми вкладкам подшивки
(`AnalyticsSubNav.vue:9-18`) — восемь полных ответов. Обещание прежнего контракта «heavy кеш 5 мин

**Решено 2026-09-09 (П45):** обязан. Все восемь вкладок считаются на **одну отметку времени**, и
сервер присылает её в ответе; **пользователю её не показывают** — она гарантия связности цифр, а
не элемент интерфейса. Имени у поля сегодня нет ни в одном домене, его задаёт этот файл
([§23](00-conventions.md)).

**6. Восемь страниц закрыты тарифным флагом, а не правом.** Восемь маршрутов гейтятся только
фича-флагами — `adminDashboard`, `adminWarehouse`, `adminSales`, `adminSupply`, `adminStaff`,

внутри дашборда ещё две секции — флагами `dashboardAlerts`/`dashboardCharts`

## Обязанности сервера

Девять граф, все заполнены наблюдениями по коду. Ответ «нигде» — не решение контракта, а строка в

**1. Значения по умолчанию и их владелец — валюта домена вшита в перевод.** Единица `unit_eur`

`DashboardPage.vue:100`). Ещё в трёх местах символ валюты вшит прямо в шаблон: `+ ' €'`
(`DashboardPage.vue:131`), `{{ client.value.toLocaleString() }} €` (`SalesPage.vue:84`),
`{{ rev.value.toLocaleString() }} €` (`StaffPage.vue:124`). И сам мок вкладывает знак в строку
значения, причём непоследовательно: `'€248 000'` префиксом (`mocks/analytics.ts:159`) против
`'26 000 €'` суффиксом (`:231`). Владелец валюты при этом — настройки:
`AppSettings.currencies` ([`types/settings.ts:239`](../../../frontend_vue/src/types/settings.ts)) и
`constants.defaultCurrency` (`:17`, дефолт `'EUR'` в состоянии композабла

пусто. То же с единицами: `'т'`, `'шт.'`, `'поз.'`, `'дн.'` — литералы перевода
(`i18n/admin/analytics.ts:6,7,42,111`) при справочнике `AppSettings.uoms` (`types/settings.ts:240`).
Отдельная величина того же класса — период отчёта (правило домена №1).
**Решено 2026-09-07:** период — текущий месяц с 1-го числа по сейчас, считает сервер (П27). Денежные числа отдаются **списком по валютам, по числу на валюту**, а не одним числом: курса в проекте нет, честно свести к одной валюте нечем (П24). Валютой и единицами владеют настройки (П19), литералы `EUR` в словаре переводов и в шаблонах — дефект.

**2. События и уведомления — домен не рождает ни одного.** `grep -c "notify"
src/services/mocks/analytics.ts` → `0`; ни один из семи эмиттеров
([`mocks/notifications.ts:542,566,592,616,637,657,684`](../../../frontend_vue/src/services/mocks/notifications.ts))
аналитики не касается — `grep -cin "analytic" src/services/mocks/notifications.ts` → `0`. Для
чтения это ожидаемо, и обратная сторона тоже верна: домен **потребляет** те же события с другой
стороны — «Запас листа 2 мм критически мал», `status: 'critical'` (`mocks/analytics.ts:88-97`)
описывает ровно то, о чём складской мок шлёт `notifyStockDeficit`
([`services/mocks/warehouse.ts:1710`](../../../frontend_vue/src/services/mocks/warehouse.ts)). Связи между
этими двумя источниками в коде нет: массив `alerts` — литерал (`mocks/analytics.ts:88-134`), из
уведомлений он не строится. Правило «событие — это переход, повтор не пишет ничего» —
`00-conventions.md`, §10.
**Решено 2026-09-09 (П55):** ни тем, ни другим по отдельности — тревога есть **проекция ленты**.
Событие рождает уведомление, уведомление помечается особым флагом «требует действия сейчас», и
`alerts` показывает помеченные: просроченные платежи, нехватку под подтверждённый заказ, партии на
исходе. Отсюда две обязанности: флаг у записи ленты и `AlertItem`, несущий то же, что несёт строка
ленты, — сегодня у него нет ни идентификатора, ни ссылки на сущность (`types/analytics.ts:31-37`),
и по тревоге некуда перейти. См. [§10.4](00-conventions.md).

Прежняя формулировка строки: чем сервер обязан наполнять `alerts` — теми же событиями или отдельным
правилом.

**3. Запись в аудит-лог — чтение следа не оставляет, и это единственное, что известно.**
`grep -c "auditLog" src/services/mocks/analytics.ts` → `0`; замкнутый перечень сущностей ленты
аудита аналитики не содержит — девять типов, все чужие

себестоимость видны не всякой роли, см. графу «Права») — в домене не выражено ничем.
**Осталось:** строка 7.

**4. Кастомные поля — домен их не касается ни в одну сторону.**
`grep -cn "fieldValues\|fieldDefinition\|customField" src/types/analytics.ts
src/services/mocks/analytics.ts` → `0` и `0`; разрезов по кастомному полю товара нет ни в одном из
девятнадцати массивов ответа (`types/analytics.ts:216-251`), хотя определения полей существуют

кастомными разрезами никто не просил, и запрета в коде тоже нет. Строки владельцу графа не даёт.

**5. Настройки, которых мок не отслеживает — все до единой.** Мок аналитики импортирует **только
типы**: `grep -c "^import " src/services/mocks/analytics.ts` → `2`, оба `import type`
(`mocks/analytics.ts:1-23`), — то есть не читает ни `MOCK_SETTINGS`, ни один чужой стор, в отличие
от складского мока, который `MOCK_SETTINGS` импортирует явно (`services/mocks/warehouse.ts:42`).
Практическое следствие измеримо: ставка НДС (`vatRate`, `types/settings.ts:15`), маржа по
умолчанию, валюта, единицы и набор статусов заказа меняются в настройках — числа аналитики не
двигаются никогда. Под моками все данные домена литеральны, дат в них нет вовсе:
`grep -c "new Date\|Date.now\|createdAt" src/services/mocks/analytics.ts` → `0`.
**Осталось:** строка 15 — подтвердить, что отчёт действительно не зависит ни от одной настройки
арендатора, или назвать зависимости.

**6. Мультиарендность — во фронте не выражена ничем, а выборка обязана быть ограничена.** Клиент
не шлёт ни `tenantId`, ни заголовка: единственный вызов идёт без `options`
(`analyticsService.ts:5`), а `options?.headers` — единственный источник заголовков у `GET`
(`services/api.ts:157-159`); `grep -cin "tenant\|user_id\|userId"
src/services/mocks/analytics.ts` → `0`. У соседних доменов с живым бэкендом заголовок есть —
`Authorization: Bearer` из `authHeaders()`
([`useAuth.ts:101-108`](../../../frontend_vue/src/composables/useAuth.ts)). На стороне схемы
арендатор обязателен у всех сущностей, из которых отчёт считается: `tenant_id` у шести складских
таблиц ([`warehouse/shared/models.py:16,96,136,173,207,234`](../../../backend/app/modules/warehouse/shared/models.py))
и у трёх финансовых ([`finance/shared/models.py:16,63,98`](../../../backend/app/modules/finance/shared/models.py)).
Общее правило — `00-conventions.md`, §4: арендатор берётся из токена и только из него, а ответ,
сшитый из нескольких источников, обязан фильтровать каждый. Для этого домена второе — не общая
фраза, а весь состав ответа. БАГ-02.
**Осталось:** строка 10 — как сервер узнаёт арендатора, чей отчёт считать (правка клиента сама по
себе на это не отвечает).

**7. Права — в какой функции проверяются: нигде, ни во фронте, ни на сервере.** Гейт только
тарифный (правило домена №6): восемь маршрутов на фича-флагах (`router/index.ts:92,98,104,110,116,122,128,134`;
значения — константы `true`, [`config/featureFlags.ts:6-13`](../../../frontend_vue/src/config/featureFlags.ts)),
плюс две секции дашборда (`featureFlags.ts:30-31`). В матрице прав аналитики нет —
`grep -cin "analytic\|dashboard\|report" src/services/mocks/config.ts` → `0`, а серверная проверка
прав вообще заглушка, возвращающая `True`
([`auth/internal_api/interface.py:27-38`](../../../backend/app/modules/auth/internal_api/interface.py)).
Три права заказов, которые прямо про видимость денег — `seeCost`, `manualCost`, `correction`
([`useOrderPermissions.ts:28-30`](../../../frontend_vue/src/composables/useOrderPermissions.ts)), —
на P&L и на себестоимость складского отчёта не влияют никак:
`grep -cn "useOrderPermissions\|seeCost" src/views/admin/analytics/*.vue` → `0` во всех восьми.
Общая рамка (два механизма прав, третий — тариф; «сокрытие себестоимости в интерфейсе — занавеска,
а не право») — `00-conventions.md`, §6.

**Но словарь тарифных флагов у сервера уже есть, и он тот же.** Все десять ключей домена засеяны в
`feature_definitions` миграцией — списком `FEATURE_FLAGS` из позиционных кортежей
`(key, name, description, level, is_system)`, который уезжает в таблицу одним `bulk_insert`
(`8cf3bfa380dd_phase_12_plans_multi_role.py:255-274`): восемь страничных с четвёртым элементом
`"page"` (`:27,30,33,36,39,42,45,48`) и два секционных `dashboardAlerts`/`dashboardCharts` с `"section"` (`:89,92`).
Колонка `level` объявлена `String(20)` с умолчанием `page`
([`billing/shared/models.py:147-149`](../../../backend/app/modules/billing/shared/models.py)), а
сама таблица — «Registry of all known feature flag keys — single source of truth»
(`billing/shared/models.py:137-138`).
Эндпоинта между этим реестром и константой фронта нет ни одного, роутов у модуля `billing` — ноль.
Один и тот же словарь существует дважды и синхронизируется руками — частный случай засеянного
решения владельца №1 (`00-conventions.md`, §7), замеренный на этом домене.
**Решено 2026-09-07.** Строка 8: **аналитика названа поимённо среди мест, где сервер вырезает
себестоимость**, а не занавешивает её — P&L и себестоимость обязаны отсутствовать в ответе
пользователю без права, а не приходить и прятаться (П5, [§6.7](00-conventions.md)); само право — обычный элемент
CRUD-матрицы по надобности роли (П2, П7). Выручка при этом закрывается **отдельным** правом, не
тем же (П6). Строка 9: **`adminWarehouse` разделяется** — отчёт `analytics/warehouse` и семь
операционных страниц склада получают разные ключи (П14, [§7](00-conventions.md)). Строка 16: **нет, не читает**, и
это подлежит исправлению — источник истины реестра фич серверный, эндпоинт чтения требуется
(П13, [§7](00-conventions.md)).

**Решено 2026-09-07 (П16):** право на выручку по умолчанию у **владельца, админа и бухгалтера** —
бухгалтер знает все финансовые отчёты, выручку в том числе. Отдельным от себестоимости оно при
этом остаётся: совпадение состава с сегодняшним `seeCost` не делает их одним правом.

**8. Транзакционность и идемпотентность — не применимо по составу домена, и это доказуемо.** Ни
одной записи: `grep -c "apiPost\|apiPut\|apiPatch\|apiDelete\|apiUpload"

`sales-crm`, та же графа его аудита.
**Осталось:** строка 11.

| «Query (опц., будущее): `{ from, to, granularity }` — резервируем» (`03-api-contract.md:704`) | в коде этого нет ни в каком виде: параметров у вызова нет (`analyticsService.ts:5`), периода в ответе нет (`grep -c "asOf\|generatedAt\|timestamp" src/types/analytics.ts` → `0`). Нужен период — это новая работа, а не восстановление описанного; см. правило №1 и строку владельцу 1 |
| «heavy кеш (5 мин per-user)» (`03-api-contract.md:717`) | кеша нет ни на одном уровне: состояние заново на каждый вызов (`useAnalytics.ts:7-9`), общего стора нет, восемь вкладок — восемь запросов (правило №5). То же снято и в `00-conventions.md`, §21 |
| «Permission `read` на соответствующий модуль» (`03-api-contract.md:717`) | проверки права нет ни во фронте (гейт только фича-флагами, `router/index.ts:92,98,104,110,116,122,128,134`), ни на сервере (модуля нет, а общая проверка — заглушка `return True`, `auth/internal_api/interface.py:27-38`). Строка владельцу 8 |
| «section previews (8 виджетов-карточек)» (`03-api-contract.md:722`) | карточек семь: `sectionPreviews` содержит `warehouse`, `sales`, `supply`, `staff`, `logistics`, `deficit`, `pl-report` (`mocks/analytics.ts:136-241`) — сам дашборд в свои превью не входит |

**Осталось:** строка 17 — оба обещания из `03-api-contract.md:717`, кеш и право, снимаются здесь как **описание
существующего**, а не как замысел; подтвердить их или оставить заданием бэкенду решает владелец
(там же строки 11 и 8).
