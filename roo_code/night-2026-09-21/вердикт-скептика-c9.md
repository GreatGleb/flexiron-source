## 5. Миграция: ревизия, SQL, жизнеспособность

**Чем проверял:** `alembic heads`, обе офлайн-генерации SQL, чтение файла ревизии, `git status`/
`git diff` каталога версий, сверку с конвенцией репозитория.

```
$ cd backend && python3 -m alembic heads
c9e4a1f70b23 (head)                       ← голова одна, ровно одна новая ревизия

$ python3 -m alembic upgrade b3f7a2c94d10:c9e4a1f70b23 --sql
CREATE TABLE warehouse_map (
    id UUID DEFAULT gen_random_uuid() NOT NULL,
    tenant_id UUID NOT NULL,
    map_file_id VARCHAR(255) NOT NULL,
    file_metadata JSONB DEFAULT '{}' NOT NULL,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT now() NOT NULL,
    updated_at TIMESTAMP WITH TIME ZONE DEFAULT now() NOT NULL,
    PRIMARY KEY (id),
    FOREIGN KEY(tenant_id) REFERENCES tenants (id) ON DELETE CASCADE
);
CREATE UNIQUE INDEX ix_warehouse_map_tenant_id ON warehouse_map (tenant_id);

$ python3 -m alembic downgrade c9e4a1f70b23:b3f7a2c94d10 --sql
DROP TABLE warehouse_map;

$ git status --porcelain -- backend/alembic/versions/
?? backend/alembic/versions/c9e4a1f70b23_settings_c9_warehouse_map.py     ← только новый
$ git diff --name-only -- …/b3f7a2c94d10_*.py …/7c4d1e9a3b58_*.py    → пусто (не тронуты)
```

`down_revision = "b3f7a2c94d10"` — совпадает с заявленным (= голова c2); ревизия ровно одна; прежние
ревизии не тронуты.

**Жизнеспособность, а не существование:**

- **`file_metadata JSONB DEFAULT '{}' NOT NULL` — звук.** Колонка объявлена `NOT NULL` с непустым
  умолчанием, поэтому на непустой таблице `CREATE TABLE` не упасть не может — но таблица к тому же
  новая (карты до этой ревизии не существовало), так что заполнять нечего.
- **`map_file_id VARCHAR(255) NOT NULL` безопасен:** строка заводится этой же ревизией, бэкфилла нет.
- **`CREATE UNIQUE INDEX ix_warehouse_map_tenant_id` обоснован моделью:** `tenant_id` объявлен
  `unique=True, index=True` (синглтон — одна строка на арендатора), и код это предполагает:
  [`get_map()`](../../backend/app/modules/settings/features/warehouse_map/repository.py:35) читает
  строку через `scalar_one_or_none()` по `tenant_id`, то есть ждёт ровно одну. Уникальность и индекс
  совпадают с этим ожиданием.
- **Обратный ход — истинный обратный:** `DROP TABLE warehouse_map` снимает таблицу, её уникальный
  индекс и FK разом; ничего сверх созданного ревизия не оставляет. `uploaded_files` не трогается ни
  вверх, ни вниз.
- **`JSONB`, а не `JSON`, — и это конвенция репозитория.** Объектные колонки в существующих
  миграциях заведены `postgresql.JSONB(... server_default="{}")` — 18 миграций, например
  [`a8dd7d7ba74b`](../../backend/alembic/versions/a8dd7d7ba74b_phase_6_suppliers.py:30)
  `company_translations JSONB NOT NULL server_default="{}"`, и в самой модели `settings`
  (`name_translations` на строках 84/105/155). Плоский `JSON()` в репозитории применён к **массивам**
  (`server_default="[]"`: `file_ids`, `tags`, `bcc_emails`). `file_metadata` — объект `{}`, значит
  `JSONB` — тип именно по конвенции, а не отсебятина. Бриф говорит «метаданные в JSON» словом, а не
  типом.

**Чего офлайн-доказательство не доказывает, и отчёт это говорит прямо (правило 4):** что DDL
применится к живой схеме. Живой цикл `upgrade head && downgrade -1 && upgrade head` **не выполнялся**
— `asyncpg.exceptions.InvalidPasswordError` (блокер среды). Это записано в §5 и §7.1 отчёта; я
подтверждаю: **живой проверки миграции НЕ было**, ни один эндпоинт карты не вызывался.

## 8. П31 — снятие пометки черновика и его транзакция

**Чем проверял:** чтение [`clear_draft_mark()`](../../backend/app/modules/settings/features/warehouse_map/repository.py:56)
и связки в [`save_warehouse_map()`](../../backend/app/modules/settings/features/warehouse_map/domain.py:130).

```
repository.py:73-82
    result = await db.execute(
        update(UploadedFile)
        .where(
            UploadedFile.id == file_id,
            UploadedFile.tenant_id == tenant_id,
            UploadedFile.is_draft.is_(True),
        )
        .values(is_draft=False)
    )
    return result.rowcount or 0
```

Это **оператор, а не упоминание**: `UPDATE … SET is_draft=false WHERE id=… AND tenant_id=… AND
is_draft IS true`, scoped арендатором. В `save_warehouse_map` он вызывается
([domain.py:164](../../backend/app/modules/settings/features/warehouse_map/domain.py:164)) **до**
`upsert_map`, а единственный `commit()` делает [`upsert_map`](repository.py:101) — обе записи
(снятие пометки и строка карты) идут **одной транзакцией сессии**, поэтому упавшее сохранение не
оставит файл подтверждённым.

**Честная оценка практической ценности:** механизм загрузки/черновиков сегодня не работает ни одним
звеном (загрузчик жёстко пишет `is_draft=False`, `draft_ttl_hours` не читается,
`expires_at` не заполняется, уборщика нет), поэтому снятие пометки — **no-op на практике**. Это
**прямо сказано** в §7.2 отчёта. Обязательство слайса было «снять флаг» (**выполнено**), а не
«построить уборщик» (вне объёма, по прямому указанию брифа) — чинильщика **не требую**.

## Находки

- **Н1 · Перенумерация c9 унаследовала слабость `renumber-c2.py`, и отчёт это отчасти маскирует.**
  Скрипт переносит ссылку по признаку «строка была в `HEAD`», а не «ссылка была верной». Два видимых
  следствия: (1) **списки через запятую переносятся наполовину** — `main.py:82,71,72,73` →
  `main.py:85,71,72,73` (дубль `71`, три номера не сдвинуты) в
  [`audit/auth.md`](../../roo_code/plans/api/audit/auth.md:37) и
  [`api/auth.md`](../../roo_code/roo-context/api/auth.md:212); (2) **уже мимо-ссылки увезены в новое
  мимо** (`main.py:74-82` → `69-77` «девять роутеров» при роутерах на `109-119`; `main.py:77` → `66`
  «монтирование статики» при монтировании на `106`). Сверх того, амбигуити-страховка
  (`new_raw in head_text`, [`renumber-c9.py:124`](renumber-c9.py:124)) **молча пропускает** замену —
  в [`contract-sync-uploads-bugs.md`](../../roo_code/plans/bugs/contract-sync-uploads-bugs.md:519)
  `main.py:77` осталось, хотя строки 186/195 того же файла уехали на `:66`. **Ни одна из этих ссылок
  не увеличила число битых** (пофайлово — 0 роста, §3), поэтому это находка к сведению оркестратора,
  а не отказ. Отдельно: §6.3 отчёта приводит `main.py:77` как пример ссылки, **не** перенумерованной
  («вне измеряемого набора»), — но этот ref живёт в `api/uploads.md`/`audit/uploads.md`, то есть
  **внутри** набора, и **был** перенесён (`63 → 66`). Пример в отчёте приписан не тому классу файлов.
- **Н2 · Дефект сторожа П11 (см. §10).** `приёмка.sh:104` считает `map_url` подстрокой по всему
