# Ночная работа 2026-09-21 — брифы под DeepSeek в Zoo Code

## Чем и как это запускается

Исполнитель — **DeepSeek в расширении Zoo Code** (`zoocodeorganization.zoo-code-3.82.2`,
установлено). У расширения **нет headless-режима**: в его `package.json` нет ни `bin`, ни
исполняемого файла, а из двадцати команд задачу заводит `zoo-code.newTask` — команда панели,
не оболочки. Значит очередь контроллером не гоняется, и ночь выглядит так:

1. открыть VSCode на этом checkout;
2. в панели Zoo Code выбрать профиль DeepSeek;
3. **новая задача на каждый бриф** — вставить содержимое одного файла `settings-c*.md`;
4. после ответа модели прогнать `./приёмка.sh <слайс>` и читать ЕГО, а не ответ модели.

Команды Zoo Code подтверждает сам: `alwaysAllowExecute` и `allowedCommands: ["*"]` в
[`../zoo-code-auto-approve.json`](../zoo-code-auto-approve.json), подключённом через
`zoo-code.autoImportSettingsPath`. То есть DeepSeek может гонять проверки сам — и брифы
этого от него требуют. Но **вердикт всё равно снимается скриптом**: слово исполнителя о
собственной работе доказательством не является.

> **Почему не контроллер.** `codex-night.py` жив и исправен (preflight пройден,
> `test_codex_night.py` — 33 passed, 23 subtests), но он запускает `codex`, а тот говорит
> только на OpenAI Responses API: провайдер с `wire_api = "chat"` — а именно такой у
> DeepSeek — отвергается на загрузке конфига («`wire_api = "chat"` is no longer supported»).
> Гонять этот же список через Codex/OpenAI можно без единой правки: очередь в формате
> [`../workflows/codex-backend-queue-2026-09-18.json`](../workflows/codex-backend-queue-2026-09-18.json),
> запуск —
> `python3 roo_code/workflows/codex-night.py --workspace ../flexiron-night-2026-09-17 --queue <очередь> --codex ~/.vscode/extensions/openai.chatgpt-26.908.40401-linux-x64/bin/linux-x86_64/codex --run`.

обработчика, приедет пятисотым; C5 и C15 между собой независимы. C0 не зависит ни от чего и может идти первым или последним.

## Правила прогона

- **Ветка.** Работать на отдельной ветке, коммит на слайс. Не пушить, не мержить в `main`.
- **Коммитить перечисленными путями**, не `git add -A`: в этом дереве уже дважды работала
  вторая сессия одновременно, и `-A` заметал чужое.
- **`outputs` брифа — исчерпывающий список.** Файл вне его не правится; понадобился — это
  находка в отчёт, а не молчаливая правка.
- **Вопрос по существу = задача падает.** Автономный режим вопросов не задаёт (ROO.md,
  «Два режима»), а догадка, которую никто не увидит, хуже остановки. Чего нет в плане —
  пишется в отчёт словами «в плане этого нет».
- **`npm run verify` целиком**, а не `test:unit`: `vitest` срезает типы не проверяя, и ночь
  2026-09-20 закоммитила код, не проходящий `vue-tsc`, а сессия-скептик поставила PASS.
- **Бэкенд проверяется своим pytest.** `backend/.venv/bin/` пуст — брать системный `python3`.
- **Текстовый критерий — крайняя мера.** Критерий, который можно выполнить правкой прозы
  (докстринга или комментария), критерием не считается: два слайса из двух прошли так старую
  редакцию `приёмка.sh`. Поведение доказывается пробой (`проба` в `приёмка.sh` и инструмент
  [`проба.py`](проба.py), AST вместо grep: докстринги и комментарии в токены не попадают), а
  текстовый поиск допустим только с письменным доводом рядом — перечень такого долга лежит в
  `приёмка.sh` под заголовком «известный текстовый долг». Инверсия критериев проверяется
  [`самопроверка-приёмки.sh`](самопроверка-приёмки.sh) на одноразовой копии в `/tmp`.
- **Тест, упавший от снятого поля, чинится в том же слайсе** — даже если его файл не
  назван в «Что можно править». Это не расширение объёма: слайс, снявший колонку,
  обязан привести в порядок то, что на неё опиралось, иначе его собственная приёмка
  (`pytest` зелёным) недостижима. Менять при этом можно **только способ** проверки, а
  не то, ЧТО тест доказывает, и равенство доказывается инверсией. Прецедент — c1:
  `exchange_rate` был канарейкой мультиарендности в `test_auth_consumers.py`.
- **Правило приёмки слайса** — слайс не принимается, пока хотя бы одно его
  П-утверждение не доказано исполнением: пробой или тестом.
- **Правило пола** — `TESTS_BASELINE` поднимается ТОЛЬКО после того, как новый тест
  уехал в коммит. Пол ловит снятие теста; заставить слайс принести тест он не может —
  заставляет правило приёмки.
- **Отчёт слайса** — `roo_code/night-2026-09-21/отчёт-<слайс>.md`. Формата не
  предписано; обязательны три вещи: полный список изменённых путей, числа приёмки и
  раздел «незакрытое» без сглаживания.
- Заблокированную работу **не оставлять в стеше**: черновик уезжает коммитом на ветку
  `draft/*`. Так уже чуть не потерялись 455 строк контракта CRM.
