## 1. Что сделано по существу

Четыре пункта брифа, все — на текущем дереве (черновик `draft/settings-c1-parked` перенесён
руками по смыслу, cherry-pick/merge не применялись):

1. **`exchange_rate` у валюты снят (П23).** Колонка удалена из модели, поля нет в
   `CurrencyResponse`, `CurrencyCreateInput`, `CurrencyPatchInput`; домен больше не читает и не
   пишет её. **БАГ-05 закрыт вместе с полем**: против настоящего сервера `POST
   /api/settings/currencies` больше не требует обязательного поля, которого фронт не шлёт.
2. **`CASCADE` → `RESTRICT` у правил пересчёта (П44).** Обе ссылки `uom_conversions.from_uom_id`
   и `.to_uom_id` на `uoms.id` переведены на `RESTRICT` — и в модели, и в миграции
   (`drop_constraint` по имени `uom_conversions_*_uom_id_fkey` + `create_foreign_key`). Каскад
   снят. **Доменного отказа по правилам пересчёта этим не заведено** — он приходит слайсом C4/§2;
   до него удаление единицы с живым правилом упирается в ограничение БД, а не в код каталога.
3. **`default_currency` перестал быть хранимой колонкой (П22 + П68).** Колонка удалена из
   `GlobalConstants`; поля нет в `ConstantsResponse` и `ConstantsPatchInput`, домен его не
   читает и не пишет. Инвариант «ровно одна валюта с флагом» и выработка значения **не
   строятся** — это слайс C6.
4. **Миграция.** Одна ревизия `7c4d1e9a3b58_settings_c1_derived_and_restrict.py` на все три
   изменения, вверх и вниз. `down_revision = "1c9d4f7b2e83"` — текущий head цепочки. Новых
   моделей нет → `_alembic_imports.py` не менялся.
5. **Контракт** [`settings.md`](../../roo-context/api/settings.md) приведён в соответствие:
   разделы `GET`/`PATCH /api/settings/constants`, `GET`/`POST`/`PATCH /api/settings/currencies`,
   `DELETE /api/settings/uoms/:id`, таблицы «Обязанности сервера», «Чего в домене нет»,
   «Пробелы аудита» и «Согласованные правила».

### 2.2 Механическая перенумерация остальных ссылок

Ссылок **без утверждаемого токена** резолвер не печатает вовсе (в `settings.md` таких 351), а они
тоже поехали от сдвига строк. Поэтому они перенумерованы тем же слайсом механически: карта
«старая строка → новая» строится по содержимому файла (`difflib` между `HEAD` и диском,
равнодлинные блоки — строка в строку, остальное — по совпадающим якорям). Переносится только
ссылка, которая **была верной до правки**: если она битая уже в HEAD, она не трогается вовсе.

- `:34`, `:73` — `assertEqual(1, row.exchange_rate)`: доказательство, что чужую валюту не тронули;
- `:46` — `assertEqual(2, …exchange_rate)`: доказательство, что свою валюту тронули;
- `:68` — `patch_currency(..., {"exchange_rate": 9})` → `sqlalchemy.exc.CompileError: Unconsumed
  column names: exchange_rate`.

Других полей эти проверки не используют. Колонки больше нет по П23, поэтому тесты обязаны
сменить «канарейку» — например, на `name_translations` (он уже используется рядом, `:35`):

```python
# :34   self.assertEqual(1, row.exchange_rate)                ->  self.assertEqual({"en": "B dollar"}, row.name_translations)
# :46   assertEqual(2, …exchange_rate)                        ->  assertEqual({"en": "A dollar"}, …name_translations)
# :68   patch_currency(db, self.currency_b, self.tenant_a, {"exchange_rate": 9})
#                                                              ->  {…, "name_translations": {"en": "hacked"}}
# :73   assertEqual(1, foreign.exchange_rate)                  ->  assertEqual({"en": "B dollar"}, foreign.name_translations)
```

**Я этот файл не правил.** Бриф (`settings-c1.md`, «Что можно править») его не перечисляет, а
README (стр. 58) прямо говорит: «Файл вне его не правится; понадобился — это находка в отчёт».
Одновременно приёмка брифа требует `pytest tests -q` зелёным. **Это противоречие брифа**, и
разрешить его может только оркестратор: либо расширить `outputs` c1 этим файлом и применить
патч выше, либо завести отдельную подзадачу. Пока не разрешено — слайс по букве собственной
приёмки НЕ пройден, хотя его работа (схема + миграция) доказана и всеми остальными проверками
зелёная.
