# Диагноз пробного прогона night-queue — 2026-09-12

Пробный режим: Ф0 (подготовка) → Ф1 (раскрой) → три круга «критик → починка» → этот диагноз → стоп.
Всё, что ниже, я перемерил сам, на живых файлах `/tmp/night-queue-briefs/` и на
`roo_code/workflows/night-queue.js` в его текущем виде. Отчётам кругов я не верил.

## 1. Пускать ли ночь

**НЕТ.**

Потому что раскрой не сошёлся: после трёх кругов в брифах осталось два неисправленных дефекта
(из файла решений выпало 676 строк текста владельца, из тел находок вырезано доказательство
дефекта), а четыре дефекта сидят в самом скрипте и кругами не чинятся — в том числе тот,
из-за которого агент `orders` получит приказ читать 102-килобайтный файл «по разделам
навигатора», которых в навигаторе нет.

Отдельная причина, не менее весомая: проба потрогала две фазы из одиннадцати. Восемь рабочих
фаз, фиксатор, скептик и механизм потолка расхода не исполнялись ни разу (раздел 4).
«Проба прошла» ≠ «прогон проверен».

## 3. Дефекты скрипта

Четыре. Кругами не чинятся по замыслу пробного режима (night-queue.js:175-181): артефакты в
`/tmp` стоят копейки и переделываются, а скрипт распоряжается всем потолком ночи.

Порядок — по цене ошибки.

### 3.2. `contextRules()` называет агентам размеры брифов, которых нет

**Что просит промпт.** night-queue.js:349-350, уходит в каждый промпт ночи:

```js
`   Навигатор покрывает roo_code/. САМИ БРИФЫ в него не входят, а шесть из них крупнее`,
`   60 КБ (решения-settings 98, решения-auth 82, решения-warehouse 79, сам навигатор 105).`,
```

**Что из этого выходит.** Числа — литералы прошлого прогона. Замер сегодняшней нарезки:

```
$ find /tmp/night-queue-briefs -maxdepth 1 -name "*.md" -size +60k | wc -l   →  1  (заявлено «шесть»)
решения-settings.md   65 834 Б  (заявлено 98 КБ)   ← единственный, кто перешагнул порог
решения-suppliers.md  54 047 Б  (в правиле не назван вовсе, а он второй по величине)
решения-warehouse.md  48 952 Б  (заявлено 79 КБ)
решения-auth.md       17 136 Б  (заявлено 82 КБ — ошибка в 4,8 раза)
навигатор.md          33 383 Б  (заявлено 105 КБ)
```

Цена двусторонняя. Агент `auth`, поверив, что его бриф 82 КБ, попадёт под следующее же правило
(«больше 60 КБ не читается целиком») и разменяет одно чтение 17-килобайтного файла на grep плюс
несколько sed — преамбула, введённая ради экономии, заставит тратить лишние вызовы. А
`решения-settings.md`, единственный реальный нарушитель, попадает под запрет без способа его
исполнить: брифы в навигатор не входят по замыслу.

**Правка.** `contextRules()` вызывается после фазы раскроя, брифы к этому моменту на диске.
Сделать функцию считающей, а не декларирующей. night-queue.js:344-351:

```js
function contextRules() {
  const big = fs.existsSync(BRIEFS)
    ? fs.readdirSync(BRIEFS).filter((f) => f.endsWith('.md'))
        .map((f) => [f, fs.statSync(`${BRIEFS}/${f}`).size])
        .filter(([, s]) => s > 60 * 1024)
        .sort((a, b) => b[1] - a[1])
    : []
  const sizes = big.length
    ? `крупнее 60 КБ ${big.length}: ${big.map(([f, s]) => `${f} ${Math.round(s / 1024)} КБ`).join(', ')}`
    : 'все брифы меньше 60 КБ — свой бриф читай целиком, одним чтением'
  …
    `   САМИ БРИФЫ в навигатор не входят; ${sizes}.`,
```

Минимальный вариант, если правка кода нежелательна, — вычеркнуть строку 350 целиком и оставить
уже стоящее рядом правило «оглавление брифа снимается `grep -n "^### П" <бриф>`». Ложные числа
хуже отсутствующих: по отсутствующим агент сделает `stat`, по ложным — не сделает ничего.

## 4. Чего проба не проверила

Пробный режим (night-queue.js:175) — это `Ф0 → Ф1 → приёмка раскроя → диагноз → стоп`. Из
одиннадцати фаз исполнены две. Не испытано ничего из списка ниже, и говорить «прогон проверен»
на этом основании нельзя:

| не исполнялось | почему это существенно |
|---|---|
| **Мок-долг** (196 мест `throw new Error` по доменам) | самая массовая правка кода за ночь — ни одной строки кода в пробе не изменено |
| **Учёт** (перетриаж группы В, делта-2) | единственная фаза, где агент меняет статусы находок, а не файлы |
| **Контракт** (П33, П34), **Сквозное** (6 планов + сводка) | не запускались |
| **Домены** — 17 планов реализации | главный объём ночи; именно сюда бьют дефекты 3.1 и 3.4, и ровно они не проверены на деле |
| **Сквозное: закрытие**, **Финал** | не запускались |
| **Фиксатор** (`commitWave`) | ни одного коммита не сделано. Поведение при грязном дереве, при чужих файлах в `git add`, при гонке за `index.lock` — не испытано |
| **Скептик** (`judged`) | ни разу не вызван на рабочем результате. Критик раскроя — другой агент и другая схема; из того, что критик умеет придираться к нарезке, не следует, что скептик поймает плохой план домена |
| **Две попытки на задачу** (`MAX_ATTEMPTS`), передача причины отказа в попытку 2 | сработало только внутри кругов раскроя, на рабочих фазах — нет |
| **Потолок расхода** 32 млн и остановка по нему (`measureSpend`, `phaseBlocked`) | механизм не срабатывал ни разу: проба съела 9,8 % и до порога не дошла. Что скрипт делает, упёршись в потолок посреди фазы «Домены», — не наблюдалось |
| **Длинная дистанция** | проба — четыре агента раскроя плюс круги. Ночь — несколько десятков агентов подряд. Деградация контекста, повторные чтения, поведение при цепочке провалов — не измерены |

Отдельно: проба проверяла **нарезку**, а не **пригодность нарезанного к работе**. Ни один
доменный агент ни разу не пробовал написать план по своему брифу. Дефекты 2.2(б) и 3.4 — оба
о том, что бриф формально полон и практически неработоспособен; такой класс ошибок проба
ловит только случайно, через дотошного критика.

## 5. Расход пробы

```
$ python3 /tmp/night-queue-briefs/расход.py
290 973 771        (оплачиваемые: input + cache_creation + output)
```

| | токенов |
|---|---:|
| отметка до пробы | 287 844 122 |
| после пробы | 290 973 771 |
| **проба стоила** | **3 129 649** |
| потолок ночи | 32 000 000 |
| **доля потолка** | **9,8 %** |

В эти 3,13 млн входят: Ф0, четыре агента раскроя, три круга «критик → починка» и этот
диагноз. Цифра растёт, пока диагноз пишется, — мерить после его закрытия, если нужна точность
до сотых.

Для масштаба: 9,8 % потолка ушло на фазу, которая не изменила ни строки кода и не написала ни
одного плана. Основания экстраполировать отсюда стоимость ночи нет — фазы разной природы, и
проба это как раз и не проверила (раздел 4). Но исходить из того, что оставшиеся девять фаз
уложатся в оставшиеся девять десятых потолка, тоже не из чего: за последние семь суток израсходовано
60 528 338 токенов, то есть ночь по потолку — это ещё половина недельного расхода сверху.
