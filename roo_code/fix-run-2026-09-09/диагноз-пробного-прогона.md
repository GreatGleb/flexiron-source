## 1. Пускать ли ночь

**НЕТ.**

Раскрой не сошёлся: после трёх кругов «критик → починка» в брифах осталось четыре дефекта, ещё

## 3. Дефекты скрипта

Каждый — «что просит промпт → что из этого выходит → чем заменить». Место указано фазой и
строкой `roo_code/workflows/night-queue.js`.

### С1. Счёт эндпоинтов грепом по «### » — фаза «Раскрой», раскрой 1, строка 534

**Просит:** `'Числа эндпоинтов бери из файла контракта домена грепом по разделам "### ", а'`

**Выходит:** у warehouse девять разделов вида «### 1. Значения по умолчанию…» … «### 9. Производные
значения» — это обязанности сервера, а не эндпоинты; у config один такой («### Двенадцать
эндпоинтов одним взглядом»). Нарезчик выполнил промпт буквально: 46 и 13 вместо 37 и 12, итог по
карте 185 против настоящих 175. Артефакт кругами починен, промпт — нет, следующий нарезчик
повторит.

**Заменить на:**
```
'Числа эндпоинтов: grep -cE "^### (GET|POST|PUT|PATCH|DELETE) " по файлу контракта домена.',
'Заголовок без HTTP-метода — это обязанность сервера, а не эндпоинт, и в счёт не идёт.',
'Контроль: сумма по всем 17 доменам обязана дать 175 — то же число печатает строка',
'"[контракт] сведено доменов: 17 · описано эндпоинтов: 175 из 175" в npm run test:unit.',
```
Дешевле и надёжнее: брать готовую таблицу `roo_code/roo-context/api/README.md` — её генерирует
`contractReadme.spec.ts` из инвентаря кода, она машинно верна.

### С2. Пометка «без бэкенда» ищется одной формой и без якоря — строка 535

**Просит:** `'withoutBackend — грепом "Бэкенд: (\\*\\*)?не реализован" по нему же.'`

**Выходит:** две разные беды за раз.
- Без якоря `^` греп ловит фразу вступления, где строка-метка упомянута как понятие
  (`suppliers.md:33` «у каждого раздела ниже стоит строка `Бэкенд: не реализован`»). Итог —
  `withoutBackend` больше `endpoints`: suppliers 9 из 8, services 6 из 5. Состояние, которое не
  может быть истинным ни при каких данных.
- Форма пометки не одна. У sales-crm стоит «Бэкенд: **модуля нет**» — счётчик её не видит, и
  единственный эндпоинт домена числится обеспеченным. Этот дефект дожил до конца проб.

**Заменить на:**
```
'withoutBackend — число разделов эндпоинтов, НЕ называющих файла бэкенда. Формы пометки',
'  две, обе с начала строки: grep -cE "^Бэкенд: (\\*\\*)?(не реализован|модуля нет)".',
'  Нашёл третью форму — посчитай её и назови в notes.',
'ИНВАРИАНТ, проверь перед ответом: withoutBackend <= endpoints по КАЖДОМУ домену.',
```
Инвариант в одну строку ловит весь этот класс ошибок и сработал бы в первом же круге.

### С10. Находки последнего круга приёмки не чинятся никогда — строки 800–804

**Просит:** `CUT_ROUNDS = 3` кругов «критик → починка».

**Выходит:** цикл устроен как критик → (если round === CUT_ROUNDS: `break`) → починка. Значит
третий критик работает вхолостую: всё, что он найдёт в артефактах, остаётся в артефактах. Ровно
это и случилось — четыре дефекта раздела 2 найдены на третьем круге и не тронуты, хотя три из них
правятся одной строкой каждый.

**Правка:** либо считать `CUT_ROUNDS` числом ПОЧИНОК и давать после последней контрольный круг
критика, либо после `round === CUT_ROUNDS` всё же звать починщика, а результат приёмки помечать
«починено, не перепроверено». Сейчас третий круг — это оплаченный агент, чей вывод выбрасывается.

перемерил), но в журнале ночи стоит «факт 210» против «плана 196» без объяснения. Дописать в
Ф0 границу замера: `'... mocks/*.ts, ИСКЛЮЧАЯ *.spec.ts — спеки считаются отдельно'`.

## 4. Что проба не проверила

Проба — это Ф0 «Подготовка», Ф1 «Раскрой» и приёмка раскроя. Дальше `TRIAL` уводит в диагноз и
останавливает прогон. Не исполнялось НИЧЕГО из перечисленного:

- **Шесть рабочих фаз целиком:** «Мок-долг», «Учёт», «Контракт», «Сквозное», «Домены»
  (семнадцать планов), «Сквозное: закрытие», «Финал». Это весь полезный выход ночи.
- **Фиксатор (`commitWave`).** Ни одного коммита за пробу не сделано. Поведение «по коммиту на
  задачу, `git add -- <файлы>`, не `git add -A`», обещание чистого дерева и дописывание журнала —
  не испытаны ни разу.
- **Скептик (`judged`).** Вызывается только в фазе «Домены». Ни один план не написан, ни один не
  отклонён, вторая попытка после отклонения не проверена.
- **Механизм потолка расхода — не работал вовсе.** `spent` обновляется ТОЛЬКО внутри
  `commitWave`/`measureSpend`, а они вызываются после рабочих волн. За всю пробу `spent` оставался
  нулём: расход в разделе 5 я мерил руками, а не механизмом прогона. Значит не проверены ни
  `mustStop`, ни `canStart`, ни `canRetry`, ни лестница ужимания, ни строчка «НЕ ВЗЯТЫ ПО ПОТОЛКУ
  РАСХОДА». Здесь же известный зазор: замер стоит МЕЖДУ волнами, а волна доменов — семнадцать
  агентов сразу; потолок внутри волны не проверяется никем.
- **Провал и повтор.** `MAX_ATTEMPTS`, `MAX_SILENT`, `phaseBlocked` — ни одна ветка не исполнялась:
  все четыре нарезчика ответили с первого раза.
- **Длинная дистанция.** Проба — час работы. Ночь — восемь-четырнадцать. Про поведение на длинной
  дистанции (деградация качества агентов, конфликт с живым человеком в этом же дереве, окно сессии
  в 5 часов) проба не говорит ничего.

Формулировать это надо так: **проверено, что раскрой можно нарезать и что его проверка работает.
Не проверено, что прогон умеет делать работу и останавливаться.**

## 5. Расход пробы

Команда: `python3 /tmp/night-queue-briefs/расход.py` (считает и субагентов из
`<сессия>/subagents/agent-*.jsonl`), замер снят на момент написания диагноза.

| | значение |
|---|---|
| нулевая отметка ночи | 283 246 687 |
| после пробы | 286 277 052 |
| **проба стоила** | **3 030 365 оплачиваемых токенов** |
| потолок ночи | 32 000 000 |
| **доля потолка** | **9,47 %** |
| cache_read за пробу | 77 752 714 (10 535 010 774 − 10 457 258 060); в потолок не входит |

Что из этого следует для решения:

- Проба съела почти десятую часть ночи, не написав ни строки плана. Это не перерасход: раскрой —
  разовая трата, дальше 378 КБ решений владельца не читаются семнадцать раз (1,3 МБ брифов вместо
  6,4 МБ перечитывания). Но и бесплатной подготовка не бывает, и в смету ночи эти 9,5 % входят.
- По известной скорости (~2,3 млн токенов в час) проба — примерно час работы; оставшиеся 29 млн —
  около двенадцати часов. За настоящую ночь очередь целиком не помещается, и это заложено в
  скрипте как ожидаемый исход, а не сбой.
- Число измерено руками. Механизм, который должен мерить это сам и на этом основании
  останавливать прогон, за пробу ни разу не запускался (раздел 4).
