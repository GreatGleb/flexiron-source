**Состояние:** починено, ждёт подтверждения не-автором.

по каждому из четырёх сервисов → `0`.

### Что сделано

1. **Новый `frontend_vue/src/services/authToken.ts`** — один источник правила «где лежит токен».
   Отдельным модулем, а не в `useAuth.ts`, потому что `useAuth.ts` импортирует `apiPost` из
   `api.ts`: обратный импорт дал бы цикл.
2. **`api.ts` подписывает запрос сам** — `buildHeaders()` в шести функциях
   (`apiGet/Post/Put/Patch/Delete/Upload`). Порядок слияния `{ ...base, ...authHeaders(),
   ...options?.headers }`: свои заголовки запроса (`Idempotency-Key`, `If-Match`) сильнее.
3. **Четыре копии чтения токена сведены в одну.** Удалены собственные реализации в
   `useAuth.ts`, `settingsService.ts:19`, `auditFeedService.ts:21`, `uploadsService.ts:14`.
   Четвёртая нашлась линзой Л5 уже по ходу — `router/index.ts:34`, охранник роутера; тоже
   сведена. Три из четырёх читали **только** `localStorage` — отсюда `settings/БАГ-06`.
4. **`apiUpload` больше не теряет `options`** — прокинуты в `uploadMock` → `uploadMockRoute`,
   как у `postMock`/`patchMock`. Своего поведения у них там пока нет: идемпотентность загрузки
   (`uploads/БАГ-05`) ждёт решения владельца, а без параметра путь 401 недостижим вовсе.

### Чем доказано

- **Машинная приёмка** `npm run verify` — код возврата `0`, все пять шагов: typecheck, lint
  (`--max-warnings=0`), dupes, format:check, test:unit. 41 файл тестов, 812 прошли, 2 пропущены.
- **Нового теста не было вовсе.** До правки заголовки не утверждал ни один тест: замер
  `grep -rln 'authHeaders\|Authorization\|buildHeaders' src/**/*.spec.ts tests/` → ни одного
  файла. То есть 802 зелёных теста были одинаковы до и после правки, и фикс не доказывали
  ничем. Заведён `src/services/authToken.spec.ts` — 10 утверждений.
- **Инверсия (Л9), обе красные:**
  - чтение сведено к `localStorage` только → **2 теста упали** (в том числе регресс-тест на
    `settings/БАГ-06`);
  - `authHeaders()` убран из `buildHeaders` → **4 теста упали**.
- **Риск под моками проверен замером:** моки читают заголовки только для `Idempotency-Key`
  (`mocks/index.ts:262-263`) и `If-Match` (`:1420-1421`); логики 401 в моках нет ни одной,
  значит правка под моками поведение не меняет и зелёный прогон не ложный.

## Отложено этим прогоном

- **Ручное подписывание в трёх сервисах стало лишним** и снимается отдельным коммитом:
  `settingsService.ts` — 31 место вида `{ headers: authHeaders() }`, `auditFeedService.ts` и
  `uploadsService.ts` — по одному. Значение то же (функция общая), поэтому это уборка, а не
  починка, и в один диф с содержательной правкой её мешать незачем.
- **Незаведённая находка (П46).** Кэш ключей идемпотентности у мока — `Map` на процесс без
  срока и без привязки к пути (`frontend_vue/src/services/mocks/index.ts:262-269`): повтор
  ключа на другой операции вернёт чужой ответ. Названа владельцем в П46, в баг-файлах её нет.
  Заводить — вместе с остальными правками баг-файлов.
- **Находок на заголовки нет у четырёх доменов** — `categories`, `clients`, `config`,
  `suppliers`. Код у них починен этой правкой, но запись о находке надо дописать, иначе
  класс выглядит закрытым на девяти из тринадцати.
