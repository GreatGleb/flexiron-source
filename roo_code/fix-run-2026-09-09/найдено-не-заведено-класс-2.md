# Найдено линзой Л5, не заведено в баг-файлы — класс 2

Записано 2026-09-11 по оговорке С3 [вердикта скептика](вердикт-скептика-класс-2.md).

**Почему файл существует.** `verify.md` требует: находка вне области задачи **не чинится
молча** — она уходит в bugs-file через `add-bug.md`, и только тогда линза считается
пройденной. Я нашёл эти места по ходу класса 2, счёл «другим классом, ~40 мест, вне
объёма» — и не записал никуда. От этого свип Л5 был объявлен чистым, будучи нечистым:
припаркованная находка не пачкает свип только если она **записана**.

Баг-файлы в этом прогоне править нельзя ([`README.md`](README.md), правило 1), поэтому
находки лежат здесь и подлежат переносу в `roo_code/plans/bugs/` тем же коммитом, что и
пометки `✅`.

## Дополнено 2026-09-11 по находке Н4 второго захода скептика

**Список выше был неполон, и это второй раз подряд один и тот же промах:** я записал ту
форму, которую искал грепом, и не пересчитал класс целиком. Полный счёт показа текста
исключения человеку — **38 мест** (замер: греп по `error*.value = String(…)`,
`error*.value = … instanceof Error ? ….message`, `toast.error(… ? ….message …)`,
`submitError.value = …` по `src/`, без спек).

Большинство из 38 уже описано в доменных баг-файлах. **Четыре места не упомянуты нигде** —
ни в баг-файлах, ни в списке выше:

| место | что показывается |
|---|---|
| `composables/useSupplierCard.ts:26` | `e.message` вместо фразы, загрузка поставщика |
| `composables/useSupplierCard.ts:43` | то же, сохранение поставщика |
| `composables/useWarehouseMovementCard.ts:40` | то же, загрузка движения |
| `views/admin/settings/ProfileSettings.vue:66` | то же, тостом при смене пароля |

Правило, которое из этого следует и стоит дороже самих четырёх строк: **счёт класса
делается по классу, а не по той записи, которой ты его нашёл.** Первый греп нашёл
`String(e)` и дал 4; второй, по смыслу «текст исключения доходит до человека», дал 38.
Разница — не в аккуратности, а в том, что предмет счёта задавался формой записи.

## Почему не починено этим прогоном

Каждому месту нужен **запасной ключ своего домена** — `orders/БАГ-11` получил
`orders.toast_error_load`, потому что тот существовал. Для `clients` и страницы создания
заказа такого ключа может не быть, а придумывать текст за владельца — не работа скептика
и не работа починки: это решение, а оно принимается отдельно. Правка на четыре домена без
такого решения превратится в четыре выдуманных фразы.

## Почему сторож их не ловит и ловить не должен сегодня

Сторож `apiErrorCode.guard.ts` охраняет **сравнение** кода с текстом, а здесь сравнения
нет — есть показ текста. Отдельный сторож на этот класс ввести нельзя: живых нарушителей
четыре, а шаг гейта вводится только зелёным (`verify.md`). Порядок обратный: сначала
решение о ключах, потом починка четырёх мест, и только потом сторож — уже зелёным.
